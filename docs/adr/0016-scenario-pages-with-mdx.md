# 0016. シナリオごとの専用ページを MDX で作り、共通の部品集で組み立てる

## ステータス

Accepted

## 日付

2026-10-03

## コンテキスト

[ADR-0015](0015-structure-scenario-markdown-for-display.md) では、シナリオ本文の Markdown を正とし、
記述規約の見出しに沿って全シナリオ共通の見せ方(目次・人物カード・表記の強調など)で表示する
構造化表示を作った。しかしオーナーがやりたいのは、シナリオごとにデザインを考えて作り込むことで、
共通の見せ方には次の限界があった([specs/005-scenario/spec.md](../../specs/005-scenario/spec.md))。

- シナリオごとに配色・レイアウト・演出を変えられない。
- 画像の置き方を細かく決められない(立ち絵は崩れないよう正方形に揃え、地図は載せていなかった)。
- タブ、開閉、ハンドアウトなど動きのある要素が作れない。
- NPC の情報を本文から推測して読み取るため、CCFOLIA のコマなど他ツールへの出力が不正確になりうる。

## 決定

- **シナリオ1本ごとに専用ページを持つ。** `src/scenarios/<slug>/` に次の3つを置く。
  - `index.tsx`:外枠・配色・ページ独自の演出
  - `content.mdx`:本文。地の文は Markdown、部品は JSX
  - `npcs.ts`:NPC のデータ
- **MDX は `@next/mdx` でビルド時にコンパイルする。** 専用ページは `scenario-list.ts` の `page` に
  動的 import で登録する。詳細画面は、`page` があれば専用ページを、なければ従来の整形表示を出す。
  権利表記とタブ名は、詳細画面が一括で付ける。
- **共通の部品集を `src/components/scenario/` に置き、`src/mdx-components.tsx` で MDX 全体に登録する。**
  `**〈目星〉**` などの記述規約の表記は、Markdown のまま書けば強調される。部品は CSS 変数で
  ページの配色に合わせる。
- **NPC は型付きのデータ(`ScenarioNpc`)で持つ。** NPC カードと CCFOLIA のコマは、同じデータから作る。
  コマは CCFOLIA 公式の Clipboard API (beta) の形式に従う。同 API では外部の画像を設定できないため、
  コマに立ち絵は含めない。
- **フローチャートには `mermaid` を使う。** ` ```mermaid ` のコードブロックで書け、図のあるページで
  だけ読み込む。
- **移行は1本ずつ行う。** `pnpm scenario:draft <ID>` で、既存の本文から下書き(章立てと NPC データを
  埋めたもの)を作れる。下書きの変換は、ADR-0015 で作った本文の解析(`scenario-structure-utils.ts`)を
  使う。移行したら元の Markdown は削除し、二重管理しない。
- 2026-10-02 に付けた構造化表示の印(`structured`)と表示部品は取り除く。部品は部品集に作り直した。

却下した案は次のとおり。

| 案 | 却下理由 |
| -- | -- |
| ページを TSX だけで書く | 長い地の文を JSX で書くのは負担が大きい(オーナーが MDX を選択) |
| `next-mdx-remote` などで実行時にコンパイルする | 本文はリポジトリ内にあり、実行時にコンパイルする理由がない |
| `src/app/trpg/scenario/<Id>/page.mdx` の静的ルートにする | ルートごとに権利表記・タブ名を書くことになり、1 か所で守れない。シナリオの中身が app のルート構造に混ざる |
| 目次を独自の remark プラグインでビルド時に作る | Turbopack ではプラグインを文字列で渡すため、ローカルの独自プラグインは扱いにくい。表示後に DOM から見出しを集める方式にした |
| 下書き生成に `tsx` などの実行用依存を入れる | Node.js 24 は TypeScript の型を外してそのまま実行できる |

## 影響・トレードオフ

- **良い点**
  - シナリオごとに見た目と演出を自由に作れる。
  - 画像・フローチャート・動きのある要素も、そのページに必要なものだけを足せる。
  - NPC のデータが正確になり、CCFOLIA への持ち出しが手作業なしでできる。
- **依存が増える**:`@next/mdx` / `@mdx-js/loader` / `@mdx-js/react` / `mermaid`(dev に `@types/mdx` /
  `@mdx-js/mdx`)。`mermaid` は大きいが、図のあるページでだけクライアントで読み込む。
- **移行が終わるまで2つの書き方が共存する**:従来の Markdown と専用ページ。全シナリオの移行に期限は
  設けない。
- **MDX では `{` `}` `<` が JSX として扱われる**:地の文ではエスケープが要る。下書き生成は自動で
  エスケープする。
- **Node の型の除去で直接実行する前提**:下書き生成とそこから辿る utils(`scenario-draft-utils.ts` /
  `scenario-structure-utils.ts`)は、相対 import を `.ts` 付きで書き、`@/` のエイリアスを使わない。
  このため tsconfig に `allowImportingTsExtensions` を加えた。
- **記述規約は引き続き有効**:[src/data/scenario/README.md](../../src/data/scenario/README.md) の
  表記規約は、専用ページの地の文にもそのまま適用する。専用ページの作り方は
  [src/scenarios/README.md](../../src/scenarios/README.md) にまとめた。
