# 0017. 写真を Cloudflare R2 に置き、手元のリストから圧縮して取り込む

## ステータス

Accepted

## 日付

2026-11-08

## コンテキスト

`/other/photograph` の写真は Dropbox に置き、`src/data/photograph/dropbox-link.ts` に共有リンクを
並べて表示している。運用してみて、次の問題が出てきた。

- **掲載の手間が大きい。** 現像 → 手でリサイズ → Dropbox にアップロード → 1枚ずつ共有リンクを取得 →
  リンクから `id` / `rlkey` / `st` を切り出して手書き、という流れで、縦横の向き(`orientation`)も
  手で入力している。入力を間違えると表示がずれる。
- **読み込みが重い。** 画像は 1152px・約190KB の JPEG で、Dropbox の `raw=1` はリダイレクトを挟むため
  1枚に1〜1.5秒かかる。表示幅に関係なく同じ画像を読むので、2列表示のスマホでも重さは変わらない。
- **撮影情報が残っている。** 公開している画像にカメラの機種と撮影日時が入ったままになっている。
  今後スマホの写真を載せると、位置情報も公開してしまう。
- **これから枚数が増える。** 写真はアルバム単位で見せる方針にした
  ([specs/009-photograph/spec.md](../../specs/009-photograph/spec.md))。100枚以上のアルバムも
  想定する。手作業のままでは続かない。

元の写真は `F:\Pictures` に約29,000ファイル(JPG・NEF・動画など)ある。公開するのはそこから選んだ一部で、
選んだ写真は少しずつ足していく。

## 決定

### 置き場所と配信

- **写真は Cloudflare R2 のバケットに置く。** 無料枠(保存 10GB、読み取り操作 月1,000万回、転送量無料)に
  収まる見込み。
- **配信は R2 を読む Worker を通し、`*.workers.dev` の URL で公開する。** 独自ドメインがなくても
  公式に想定された方法で公開でき、r2.dev の開発用 URL の制約(本番向けではなく、速度制限があり、
  キャッシュも効かない)を受けない。
  - Worker は指定されたパスの画像を R2 から返すだけにする。一覧の取得や書き込みはできないようにする。
  - レスポンスに長期キャッシュの指定(`Cache-Control: public, max-age=31536000, immutable`)を付ける。
    `*.workers.dev` では Cache API が使えないため、繰り返しの読み込みはブラウザのキャッシュで減らす。
  - Worker のコードはこのリポジトリに置く。
- **画像の URL はベース URL + 画像のキーで組み立て、ベース URL はコード中の1か所にまとめる。**
  将来独自ドメインを付けたら、Worker にそのドメインを割り当て、ベース URL を変えるだけで移行できる。

### 取り込み(`pnpm photo:sync`)

- **アルバムごとに、公開する写真のパスを並べたリスト(txt)を書く。** ファイル名がアルバムの URL に
  なる。

  `src/data/photograph/albums/2025-04-nemophila.txt`

  ```
  # title: ネモフィラ
  # date: 2025-04-05
  2025年\2025-04-05 ネモフィラ\DSC_0001.JPG
  2025年\2025-04-05 ネモフィラ\DSC_0008.JPG
  ```

  - パスは元の写真の置き場所からの相対パスで書く。置き場所は `.env.local` の `PHOTO_SOURCE_ROOT` に書く。
  - エクスプローラーの「パスとしてコピー」で貼った `"F:\Pictures\..."` 形式も受け付ける。スクリプトが
    相対パスに書き換え、書き換えたことを表示する。
  - `#` で始まる行と空行は、先頭のアルバム情報(`title` / `date`)を除いて無視する。
- **リスト(txt)はリポジトリ内に置くが、git の管理対象外にする。** リポジトリは公開なので、元の写真の
  フォルダ名(私的なイベント名を含む)を公開しないため。
- **スクリプトがリストを読み、圧縮・アップロード・アルバムデータの生成を行う。** 処理は次のとおり。
  - 撮影時の向き情報に合わせて回転する。
  - 幅 640px と幅 1280px の2つを WebP(画質80前後)で作り、画面の幅に合わせてブラウザに選ばせる。
    数値は実際の写真で試して決める(拡大表示がないため、それより大きいものは作らない。
    [specs/009-photograph/research.md](../../specs/009-photograph/research.md) R3)。
  - 撮影情報(Exif。位置情報を含む)を消す。
  - 似ている写真をグループにして知らせる。どれを残すかはオーナーが決め、スクリプトは削除しない。
  - R2 にアップロードし、アルバムデータ(`src/data/photograph/albums/<slug>.json`)を生成する。
- **アルバムデータ(json)はコミットする。** 中身はアルバムのタイトル・日付と、写真ごとの画像のキー・幅・
  高さだけにする。元の写真のパスは含めない。ビルドと CI はこの json だけを読み、元の写真やリストを
  必要としない。
- **画像のキーは元の写真の中身から作るハッシュにする。** 元の写真のフォルダ名を変えても、アップロード済みの
  写真は影響を受けない。同じ写真を複数のアルバムに入れても、R2 には1つだけ置く。
- **`--dry-run` を付けると何もアップロードせず**、枚数・圧縮後の合計サイズの見込み・見つからない
  ファイル・似ている写真を表示する。
- **再実行すると、増えた写真だけをアップロードする。** リストから消した写真は「R2 に残っている」と
  知らせ、`--prune` を付けたときだけ R2 から消す。どのアルバムからも参照されていない写真だけを消す。
- **リストに RAW(NEF)が書かれていたら、同じ名前の JPG を使う。** なければエラーにして、
  NX Studio で書き出すよう知らせる。
- R2 の API トークン(そのバケットへの書き込みだけを許可したもの)は `.env.local` に置く。
  `.env*.local` は `.gitignore` で除外済み。

### 移行

- 既存の72枚は、元の写真を `F:\Pictures` から探してリストに書き、同じ手順で取り込む。移行が済んだら
  `dropbox-link.ts` を削除し、Dropbox の参照をなくす。

### 却下した案

| 案 | 却下理由 |
| -- | -- |
| Dropbox のまま、API で共有リンクの取得を自動化する | アプリ登録とトークン管理が要るうえ、表示幅に合わせた画像を出せず、重さが残る |
| リポジトリ(`public/`)に画像を置く | 公開リポジトリの履歴に画像が残り、消しても縮まない。アルバム単位で枚数が増えると重くなる |
| R2 の `r2.dev` URL で公開する | Cloudflare が本番向けではないと明記しており、速度制限で 429 が返りうる |
| Cloudflare Images に保存する | 保存と配信は有料プランのみで、この規模には過剰 |
| R2 + Image Transformations でアクセス時に変換する | 無料枠は月5,000回(画像と幅の組み合わせごと)で、上限を超えたときの動作を確認できなかった |
| Workers の静的アセットとして配信する | デプロイのたびに全画像を手元に揃えておく必要がある |
| 公開する写真を別フォルダにコピーして同期する | 同じ写真がディスク上に二重にできる。オーナーがリスト方式を選んだ |
| リスト(txt)もコミットする | 元の写真のフォルダ名が公開される(オーナーが管理対象外を選んだ) |

## 影響・トレードオフ

- **良い点**
  - 掲載作業が「リストにパスを貼って `pnpm photo:sync`」だけになる。共有リンクと向きの手入力がなくなる。
  - 表示幅に合わせた軽い画像を出せる。撮影情報も公開しなくなる。
  - 写真の幅・高さが実際の値になり、表示のずれの原因が1つ減る。
  - 費用は無料枠の範囲に収まる見込み。
- **コスト・注意点**
  - Cloudflare のアカウント・R2 バケット・Worker の準備が要る。R2 の利用には支払い方法の登録が
    求められる見込み(未確認)。無料枠を超えた分は課金される。
  - Workers の無料プランは1日10万リクエストまで。超えると UTC の0時までエラーになり、写真が表示されない。
    1ページで20枚読むとして、1日約5,000回の表示までは耐える。
  - リスト(txt)は手元にしかないため、失うと編集の起点がなくなる。公開中の内容はコミットされた json に
    残るので、サイトの表示には影響しない。
  - `photo:sync` は元の写真がある PC でしか動かない。
- **実装時に確かめたこと**(2026-11-08)
  - `aws4fetch` で R2 の S3 互換 API に直接アップロードできた。
  - `https://qurioth-photos.qurioth.workers.dev` の Worker から R2 の画像を配信できた(写真のパスで 200、
    形の違うパスで 404、`POST` で 405)。`workers.dev` のサブドメインを新しく登録した直後は、証明書の
    発行を待つ数分間、HTTPS でつながらなかった。
  - 配信した画像に撮影情報(Exif)が残っていない。
  - 似ている写真は、画像の比較だけでは別の被写体を拾ったため、撮影時刻(30秒以内)と組み合わせた
    ([specs/009-photograph/research.md](../../specs/009-photograph/research.md) R9)。
