# 0015. シナリオ本文は Markdown を正とし、記述規約に沿って構造化して表示する

## ステータス

Accepted

## 日付

2026-10-02

## コンテキスト

シナリオ詳細画面(`/trpg/scenario/<シナリオID>`)は、本文 Markdown を `react-markdown` で
1 本の長い文書として整形表示していた。12 本で約 8,400 行あり、長いものは 1 本で 1,800 行を
超える。この表示方法には 2 つの問題があった
([specs/005-scenario/spec.md](../../specs/005-scenario/spec.md))。

- GM がセッション中に目的の場面・NPC・判定へすぐ辿り着けない。
- NPC の能力値・技能・セリフ例をまとまりとして見せられない。判定や正気度喪失を示す手段も、
  太字という弱い合図しかない。

これを全シナリオ共通の構造化された見せ方(目次、人物カード、能力値の格子、表記の強調など)へ
作り替えるにあたり、本文をどう持つかを決める必要があった。本文の書き方は
[ADR-0014](0014-establish-scenario-markdown-conventions.md) の記述規約でかなり型が決まって
いる。判定 `**〈技能〉**` が 239 箇所、正気度喪失 `**正気度喪失：…**` が 125 箇所あり、
能力値はすべての NPC で `STR: 55 CON: 75 …` の形になっている。

## 決定

- **本文は今までどおり `src/data/scenario/markdown/<slug>.md` の Markdown を正とする。**
  詳細画面は表示時に、記述規約の見出しレベル(`##` 章、`###` 人物・調査対象・ED、`####`
  ステータスなど)と書式に沿って本文を区画に分け、構造を組み立てて描画する。
- 区画への分割は、見出しで区切る行単位の処理として自前で実装する
  (`src/utils/scenario-structure-utils.ts`)。**新しい依存は追加しない。** 各区画の本文は
  Markdown 文字列のまま持ち、既存の `react-markdown` + `remark-gfm` で描画する。判定・
  正気度喪失・呪文などの強調は、描画部品の差し替えで行う。
- 構造化表示への移行は 1 本ずつ行い、`scenario-list.ts` のエントリに `structured: true` を
  付けたシナリオだけを構造化表示にする。それ以外は従来の整形表示のまま残す。
  クトゥルフ神話TRPG 以外のシステムのシナリオ(現状は queen-of-the-sea)は移行しない。
- 移行で本文の行が失われないことを、テストで保証する。分割結果をつなげ直すと元の本文に
  一致することを、全シナリオで確かめる。移行済みのシナリオには、章の順序・能力値の書式・
  太字の付け忘れを確かめるデータ適合テストをかける。
- GM がそのまま読み上げる描写のために、記法「読み上げ文」を加える。1 行目を
  `[!読み上げ]` だけにした引用で書く。既存の引用記法の上に乗せるので、依存も生 HTML も
  要らず、目印のない引用(セリフ)には影響しない。

却下した案は次のとおり。

- **本文を TypeScript の構造化データに書き換える**: 約 8,400 行を手で変換する必要があり、
  欠落・改変のリスクが最も高い。地の文を TS の文字列で書くのは執筆体験が悪く、ADR-0014 の
  規約も意味を失う。
- **MDX にして、部品を本文に埋め込む**: MDX ローダーの依存が増え、本文に JSX が混ざる。
  見た目は全シナリオ共通なので、シナリオごとに部品を置き分ける表現力は要らない。
- **NPC・ステータスだけ YAML などに切り出す**: 1 本のシナリオが 2 つの形式に分かれる。
  クライマックス中の神話生物のように、本文の流れの中にある記述が本文から離れてしまう。
- **`remark-parse` で構文木を得て組み替える**: pnpm では直接依存として追加が必要になり、
  位置情報から部分文字列を切り出す手間も増える。構造を決めるのは見出しだけなので、行単位の
  分割で足りる。
- **読み上げ文を言語指定付きのコードブロックや `remark-directive` で表す**: コードブロック
  では太字や改行が効かない。`remark-directive` は依存が増える。

## 影響・トレードオフ

- 良い点: 本文の書き方も執筆の流れも変わらない。新規シナリオも
  [template.md](../../src/data/scenario/template.md) から書き始められる。移行の作業は、
  見出しや太字を規約に合わせることと `structured: true` を付けることだけで済む。
- 記述規約が表示の前提になる。見出し名の揺れ(例: `## シナリオ終了報酬`)や太字の付け忘れは、
  これまでは見た目に出なかったが、構造化表示では「ED の見た目にならない」「強調されない」
  という形で表に出る。規約は [src/data/scenario/README.md](../../src/data/scenario/README.md)
  を正とし、構造化表示が前提とする条件は
  [specs/005-scenario/contracts/structured-markdown.md](../../specs/005-scenario/contracts/structured-markdown.md)
  にまとめた。
- 移行が終わるまでは、2 つの表示形式が共存する。他システムのシナリオがあるため、移行完了後も
  従来の整形表示は残る。
- 本文はモジュールの読み込み時に読まれるため、開発サーバーで Markdown だけを編集しても
  表示に反映されないことがある。その場合は開発サーバーを再起動する。
