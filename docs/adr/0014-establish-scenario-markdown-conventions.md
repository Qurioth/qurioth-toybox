# 0014. シナリオMarkdownの記述規約を定め、`src/data/scenario/README.md` に集約する

## ステータス

Accepted

## 日付

2026-08-26

## コンテキスト

`src/data/scenario/markdown/` のシナリオ本文は、書式を決めないまま1本ずつ書き足してきた。
12本たまった時点で記法が揃っておらず、次の問題が出ている。

- 同じことを表すのに複数の書き方が併存している。NPCの能力値の並び順は
  `STR DEX INT CON APP POW SIZ EDU`(11箇所)と `STR CON POW DEX APP SIZ INT EDU`(8箇所)、
  正気度喪失は `**正気度喪失：0 ／ 1**` と `**正気度喪失: 0/1D3**`、導入の見出しは
  `## シナリオの導入`(9本)と `## 導入`(2本)、といった具合に揺れている。
- 新しいシナリオを書くたびに「前はどう書いたか」を既存ファイルから探す必要がある。
  参照するファイルによって書き方が変わるため、揺れが再生産される。
- 書式の一部は描画側の制約に縛られている。詳細ページ
  ([src/app/trpg/scenario/[id]/page.tsx](../../src/app/trpg/scenario/%5Bid%5D/page.tsx))は
  `react-markdown` + `remark-gfm` だけで描画しており、`rehype-raw` が無いので生HTMLは
  出ず、`breaks` も有効にしていないので行内改行には行末の半角スペース2つが要る。また
  二次創作の著作権表記はページ側が自動で足すため本文に書いてはいけない。これらは
  ファイルを見ても分からず、知らずに書くと表示が壊れる。
- 雛形として `src/data/scenario/preparation.md` を置いていたが、コードからもドキュメント
  からも参照されておらず、CLAUDE.md にも記載が無かった。存在に気づけないため、実際には
  使われずに古くなっていた。

置き場所については、リポジトリに既にある3つの選択肢を検討した。

- **ADR**: [docs/adr/README.md](README.md) が「一度 `Accepted` になったADRの本文は基本的に
  変更しない」と定めている。書式はシナリオを書くたびに追記・調整される生きた規約なので、
  改訂のたびにADRを発行することになり運用が合わない。
- **spec**: [specs/005-scenario/spec.md](../../specs/005-scenario/spec.md) は絞り込みや本文表示
  といった画面の振る舞いを記述するもので、本文の書き方は画面仕様ではない。
  [ADR-0013](0013-spec-per-screen.md) の「1ディレクトリ=1画面」の単位も崩れる。
- **CLAUDE.md**: 規約本体は200行を超える分量があり、作業ガイドの一節に収めるには大きい。

## 決定

- シナリオ本文の記述規約を **`src/data/scenario/README.md`** に集約する。対象ディレクトリの
  直下に置くことで、GitHubで `src/data/scenario/` を開いたときに自動で表示される。
  [docs/adr/README.md](README.md) と [specs/README.md](../../specs/README.md) が既に
  「そのディレクトリの運用ルールをREADMEに書く」形を取っており、それに揃える。
- 新規シナリオ用の雛形を **`src/data/scenario/template.md`** として分離する。README は読む
  ための文書、template はコピーするためのファイルという役割分担にする。役割を表さなく
  なっていた `preparation.md` は README.md にリネームし、雛形部分を template.md に移した。
- 揺れていた記法は、**既存12本での使用数が多い側を正とする**。新しく理想形を設計するのでは
  なく実態に寄せることで、修正量と、書き手(オーナー本人)の慣れとの齟齬を最小にする。
  主な確定内容は次の通り。

  | 対象 | 確定 | 退けた側 |
  | --- | --- | --- |
  | 能力値の並び(NPC・神話生物とも) | `STR CON POW DEX APP SIZ INT EDU`(持たない能力値は飛ばす) | `STR DEX INT CON APP POW SIZ EDU` |
  | ステータス・技能のコロン | 半角 `: ` | 全角 `：` |
  | 正気度喪失 | `**正気度喪失：0 ／ 1**`(全角コロン・全角スラッシュ) | 半角コロン・半角スラッシュ |
  | 見出しの括弧 | 半角 `(…)` + 直前に半角スペース | 全角 `（…）` |
  | 導入の見出し | `## シナリオの導入`(NPCの後) | `## 導入`(NPCの前) |
  | 報酬の見出し | `### その他報酬 (任意)` | `### その他報酬（任意）` |
  | セリフ例 | 引用(`>`) | 箇条書き(`- 「…」`) |
  | NPC名・神話生物名の太字 | 使わない | 初出を `**名前**` で強調 |

  ただし能力値の並びだけは、使用数では `STR DEX INT CON APP POW SIZ EDU` が多いものの、
  オーナーの選好により `STR CON POW DEX APP SIZ INT EDU` を正とした。ここだけ多数決に
  従っていない。

  NPC名・神話生物名の太字は全廃した。規約の当初案では「初出を太字にする」としていたが、
  実態は初出に限らず(`天城 雅信` は11箇所、`渡舟 好吉` は太字3・素6)、書き手の判断で
  付いているだけで規則になっていなかった。加えて太字は判定・正気度喪失・呪文という
  「GMがその場で処理すべきもの」の合図を兼ねており、最多の210箇所を占める名前を
  太字にすると、その合図が埋もれる。名前は太字をやめ、太字の意味を処理の合図に絞る。

  正気度喪失だけ全角コロンを残すのは、`**正気度喪失：…**` が地の文に埋め込まれる強調表記
  であり、半角コロンだと前後の日本語と詰まって読みにくいため。既存の使用数でも全角が多い。
- 規約が対象とするのは **クトゥルフ神話TRPG 7版のシナリオ**とする。セクション構成(GM向け情報、
  主なNPC、クライマックス、ED…)がこのシステムを前提にしているため。他システムのシナリオ
  (`queen-of-the-sea` は「駆け出しアイドルRPG ビギニングアイドル」)は、章立てはそのシステムの
  進行に従い、改行・強調・テーブルなど表記まわりの規約だけを適用する。
- **本ADRを機に、既存12本を規約に合わせて一括で修正する**。[ADR-0013](0013-spec-per-screen.md)
  で既存9画面のspecを一度書き起こしたのと同じ考え方で、規約と実態がずれたままだと
  「どちらが正か」を毎回判断することになり、規約を作った意味が失われるため。逸脱は表記
  レベル(コロン・括弧・見出し名・能力値の並び順)にとどまり、本文の意味は変わらない。
  修正は本文の加筆・修正とは別のコミットに分け、差分が表記の置き換えだけであることを
  読めるようにする。能力値の並び替えは値の取り違えが起きうるため、機械的な一括置換では
  なく該当箇所を目視で確認しながら行う。
- CLAUDE.md に規約へのポインタを置く。`preparation.md` が使われなかった原因は存在に
  気づけないことだったので、置き場所を決めるだけでは同じことが起きる。

## 影響・トレードオフ

- 良い点: 新しいシナリオを書くときに既存ファイルを読み比べる必要がなくなる。描画側の制約
  (生HTML不可、行末スペース2つ、著作権表記の自動付与)が明文化され、知らずに踏む事故が減る。
  規約・雛形・登録先が同じディレクトリに揃うため、CLAUDE.md からのポインタ1本で辿れる。
- コスト: 一括修正で12本中9本に差分が出る。表示結果はほぼ変わらないが、`git blame` は
  その行が規約対応で書き換わったことを指すようになる。
- 規約は多数決で決めたものであり、「そう書くのが正しい」という外部の根拠があるわけではない。
  書いていて不便だと分かれば README.md を直接更新してよい。ADRの本文は変えず、規約の現在の
  内容は常に README.md を正とする。
- 対象をクトゥルフ神話TRPGに絞ったため、他システムのシナリオが増えたときに章立ての指針が
  無い状態になる。そのときに README.md へシステム別の節を足すか、判断し直す。
