# 0011. Biomeのフォーマッタを有効化する

## ステータス

Accepted

## 日付

2026-08-15

## コンテキスト

[ADR-0006](0006-migrate-eslint-to-biome.md)でESLintからBiomeへ移行した際、`formatter.enabled`
は`false`のままにしていた。lintの移行がスコープであり、整形まで一度に変えると差分が大きくなり
すぎるためである。

その結果、整形はエディタ任せとなり、ファイルごとにスタイルが揃っていない状態が続いていた。
実際、`biome format`をかけると74ファイル中70ファイルが未整形と判定された(大半は改行コードの
差分だが、末尾カンマの有無や折り返し位置の不統一も含まれる)。

リファクタリングを継続的に行っていくにあたり、整形差分と実装差分が混ざるとレビューが困難になる。
先に整形を一度で片付けておきたい。

## 決定

- `biome.json`の`formatter.enabled`を`true`にし、リポジトリ全体に`biome format --write`を適用する。
- `indentStyle`は`"space"`を明示する。Biomeの既定はタブだが、既存コードは全ファイルが
  2スペースインデントであり、タブへの変換は不要に大きな差分を生むため。`indentWidth`(2)と
  `lineWidth`(80)はBiomeの既定値が既存スタイルと一致するため明示しない。
- `.gitattributes`に`* text=auto eol=lf`を追加する。このリポジトリは`core.autocrlf=true`で
  作業ツリーがCRLFになる一方、Biomeは既定でLFを出力するため、これがないとチェックアウトの
  たびに全ファイルが未整形と判定されてしまう。
- `.specify/`をBiomeの対象外に追加する。spec-kit公式CLI([ADR-0009](0009-adopt-official-spec-kit-cli.md))
  が生成・管理する領域であり、CLIが再生成するたびに整形差分が復活するため。
- `pnpm format`(書き込み)と`pnpm format:check`(検査のみ)を追加し、CIに`format:check`
  ステップを組み込む。

## 影響・トレードオフ

- 良い点: 整形が自動化され、以降のリファクタリングで実装差分だけをレビューできる。
  CIで未整形コードが混入しなくなる。
- コスト: 今回のコミットは11ファイル・約80行に及ぶ横断的な差分になり、`git blame`が
  一部の行で本コミットを指すようになる。ただし整形のみで挙動の変化はなく、
  `git diff -w`で実質差分がないことを確認済み。
- `.gitattributes`の追加により、作業ツリーの改行コードがCRLFからLFに変わる。Windows環境の
  エディタは通常どちらも扱えるため実害はないが、既存のチェックアウトでは一度
  `git add --renormalize .`が必要になる場合がある。
