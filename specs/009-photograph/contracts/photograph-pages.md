# Contract: 写真一覧の画面

**Feature**: [../spec.md](../spec.md) | **Data**: [../data-model.md](../data-model.md)

結合テスト(React Testing Library)で確かめる振る舞い。各項目の末尾は対応する spec の要件。

## 1. アルバムの一覧 `/other/photograph`

部品: `AlbumList`(`albums` を受け取る)

1. アルバムごとにカードが1つ出る。カードには表紙の画像・タイトル・撮影日・「n枚」が出る(FR-001)。
2. カードはアルバムの画面(`/other/photograph/<slug>`)へのリンクになっている(FR-001)。
3. カードは撮影日の新しい順に並ぶ。同じ日は slug の昇順(FR-002)。
4. 表紙の画像は、そのアルバムの先頭の写真の幅 640px 版を指している(FR-003 / FR-013)。
5. アルバムが0件のときは「まだアルバムがありません」と出て、カードは出ない(Edge Cases)。
6. 幅 375px でページの横スクロールが出ない(SC-003。ブラウザで確認)。

## 2. アルバムの画面 `/other/photograph/<slug>`

部品: `PhotoGallery`(`photos` とタイトルを受け取る)。ページはタイトル・撮影日・戻る導線と
`PhotoGallery` を並べるだけ。

1. アルバムのタイトルと撮影日が出る(FR-004)。
2. アルバムの一覧(`/other/photograph`)へ戻るリンクがある(FR-004)。
3. 表示幅が分かるまで(サーバーでの描画とハイドレーション中)は、写真を並べず、場所を確保した枠だけを
   出す(Edge Cases、research R2)。
4. 写真は `justifyRows` の結果どおりの行に、登録順で入る(FR-007)。
5. 各写真の表示の幅と高さは、`justifyRows` が決めた行の高さと写真の縦横比のとおり(FR-005 / FR-006)。
6. 各画像は `width` / `height` に写真の実際の大きさを持ち、`srcset` に 640px 版と 1280px 版、
   `loading="lazy"` を持つ(FR-006 / FR-011 / FR-013)。
7. 21枚以上のアルバムでは、最初は20枚だけが出る(FR-008)。
8. 一覧の下の目印が画面に入ると20枚追加される。追加の前の最後の行より前の行は変わらない(FR-009)。
9. すべて出し終えたら目印はなくなり、それ以上増えない(FR-010)。
10. 20枚以下のアルバムでは、最初からすべて出る(Edge Cases)。
11. 画像の読み込みに失敗した枠には「画像の読み込みに失敗しました」と出る。他の写真はそのまま出る
    (FR-012 / SC-004)。
12. 読み込みが終わるまで、写真と同じ縦横比のプレースホルダが出る(FR-011)。

## 3. ルーティング

1. 登録されたアルバムの slug だけがビルド時にページになる(`generateStaticParams`)。
2. 登録されていない slug は 404 になる(`dynamicParams = false`。FR-015。ビルド後に確認)。
3. ブラウザのタブのタイトルはアルバムのタイトルになる(`generateMetadata`)。

## 4. `/other`

変更しない。Photograph の区分は今までどおり `/other/photograph` を指す
([008-other](../../008-other/spec.md))。
