# Feature Specification: 写真一覧

**Feature Branch**: `009-photograph`

**対象画面**: `/other/photograph` (`src/app/other/photograph/page.tsx`)

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "オーナーが撮影した写真をタイル状に並べて閲覧する画面。枚数が多いためスクロールに応じて少しずつ読み込む。既存実装の現行仕様を spec として書き起こしたもの。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 写真を眺める (Priority: P1)

訪問者として、オーナーが撮影した写真をまとめて眺めたい。1枚ずつ開くのではなく、並んだ状態で
流し見できるようにしてほしい。

**Why this priority**: この画面の唯一の目的。写真が並んで見えることがそのまま価値になる。

**Independent Test**: `/other/photograph` を開き、写真がタイル状に並んで表示されることで
確認できる。

**Acceptance Scenarios**:

1. **Given** `/other/photograph` を開いた直後、**When** 画面を見る、**Then** 写真が複数列の
   タイル状に並んで表示される。
2. **Given** 縦向きの写真と横向きの写真が混在している、**When** 一覧を見る、**Then** それぞれの
   向きに応じた縦横比で並び、列の幅は揃っている。

---

### User Story 2 - 枚数が多くても待たされない (Priority: P2)

訪問者として、写真の枚数が増えても最初の表示で長く待たされたくない。スクロールした分だけ
続きが出てくればよい。

**Why this priority**: 一覧できること自体は User Story 1 で足りるが、全点を一度に読み込むと
最初の表示が遅くなり、流し見という目的が損なわれる。

**Independent Test**: 画面を開いた直後に読み込まれる枚数が限られており、下までスクロールすると
続きが追加されることで確認できる。

**Acceptance Scenarios**:

1. **Given** `/other/photograph` を開いた直後、**When** 表示されている枚数を数える、**Then**
   全点ではなく決まった件数までしか読み込まれていない。
2. **Given** 一覧の下端までスクロールした状態、**When** そのままスクロールを続ける、**Then**
   続きの写真が追加で表示される。
3. **Given** すべての写真を表示し終えた状態、**When** さらにスクロールする、**Then** 追加の
   読み込みは行われず、表示も変わらない。

---

### Edge Cases

- 個々の写真が読み込まれるまでの間は、場所を確保したプレースホルダを表示し、読み込み完了後に
  写真へ差し替える。表示位置がずれてスクロールが飛ばないようにするため。
- 写真の取得に失敗した場合は、その枠に読み込めなかったことを日本語で示す。他の写真の表示は
  続ける。
- 画面幅が変わった場合(端末の回転・ウィンドウのリサイズ)は、列数が即座に切り替わる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 本画面は、写真を複数列のタイル状に並べて表示しなければならない。
- **FR-002**: 列数は画面幅に応じて切り替えなければならない。広い画面では4列、狭い画面では
  2列とする。
- **FR-003**: 初回表示では全点を読み込まず、決まった件数(20件)までを表示しなければならない。
- **FR-004**: 訪問者が一覧の下端付近までスクロールしたときは、続きを同じ件数ずつ追加で
  表示しなければならない。
- **FR-005**: すべての写真を表示し終えた後は、追加の読み込みを行ってはならない。
- **FR-006**: 個々の写真は、読み込みが完了するまでプレースホルダで場所を確保しなければ
  ならない。
- **FR-007**: 写真の取得に失敗した枠には、読み込めなかったことを日本語で示さなければならない。
- **FR-008**: 写真は、縦向き・横向きの区別に応じた縦横比で表示しなければならない。

### Key Entities *(include if feature involves data)*

- **写真**: オーナーが公開している1枚の画像。表示名、外部保管先を指す情報、縦向きか横向きかの
  区別を持つ。一覧に並ぶ順序は登録順に従う。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 画面を開いてから最初の写真が並ぶまでに、全点の読み込みを待たされない。
- **SC-002**: 下端までスクロールしたとき、続きが表示されるまで操作が止まらない。
- **SC-003**: 幅375px の端末で、横スクロールを発生させずに2列で閲覧できる。
- **SC-004**: 1枚の写真が読み込めなくても、他の写真の閲覧を続けられる。

## Assumptions

- サイト共通のヘッダー・フッター・配色切替の仕様は [001-home](../001-home/spec.md) で扱い、
  本specでは繰り返さない([ADR-0013](../../docs/adr/0013-spec-per-screen.md))。
- 写真は外部のファイル共有サービスに置いたものを参照する。サイト側に写真の追加・削除・
  並べ替えを行う画面は持たない(掲載内容の更新はデータの更新で行う)。
- 拡大表示、絞り込み、撮影情報(日時・機材)の表示は現時点では持たない。必要になった時点で
  本specを更新する(原則1)。
- 本specは既存実装の現行仕様を書き起こしたものであり、新機能の追加を含まない。
