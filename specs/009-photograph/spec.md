## User Scenarios & Testing *(mandatory)*

### User Story 1 - アルバムを選ぶ (Priority: P1)

訪問者として、どんな写真があるのかをまず一覧で知り、見たいアルバムを選びたい。写真が全部
混ざって並んでいると、どこで撮ったものか分からず、見たいものにたどり着けない。

**Why this priority**: アルバムが増えるほど、全写真を1列に並べる表示では目当ての写真が埋もれる。
入口としてアルバムを選べることが、他のすべての閲覧の前提になる。

**Independent Test**: `/other/photograph` を開き、アルバムがカードで並び、1つを選ぶとそのアルバムの
写真の画面に移ることで確認できる。

**Acceptance Scenarios**:

1. **Given** `/other/photograph` を開いた直後、**When** 画面を見る、**Then** アルバムごとに表紙の写真・
   タイトル・撮影日・枚数を載せたカードが並んでいる。
2. **Given** アルバムの一覧、**When** 並び順を見る、**Then** 撮影日の新しいアルバムが先に並んでいる。
3. **Given** アルバムの一覧、**When** 1つのカードを選ぶ、**Then** そのアルバムの写真の画面
   (`/other/photograph/<アルバム>`)に移る。

---

### User Story 2 - アルバムの写真を眺める (Priority: P1)

訪問者として、アルバムの写真をまとめて眺めたい。1枚ずつ開くのではなく、並んだ状態で流し見できる
ようにしてほしい。縦長の写真と横長の写真が混ざっていても、見やすく並んでいてほしい。

**Why this priority**: この画面の中心となる体験。写真が整って並んで見えることが、そのまま価値になる。

**Independent Test**: 縦長と横長が混ざったアルバムを開き、行ごとに高さの揃った写真が並び、各行の右端が
揃っていることで確認できる。

**Acceptance Scenarios**:

1. **Given** アルバムの画面を開いた直後、**When** 画面を見る、**Then** アルバムのタイトルと撮影日が
   表示され、写真が行ごとに高さを揃えたタイル状に並んでいる。
2. **Given** 縦長の写真と横長の写真が混在するアルバム、**When** 一覧を見る、**Then** 各写真は
   切り取られずに元の縦横比で表示され、同じ行の写真は高さが揃っている。
3. **Given** 縦長の写真と横長の写真が混在するアルバム、**When** 最後の行を除く各行の右端を見る、
   **Then** どの行も表示幅いっぱいに揃っている。横長の写真は縦長の写真より横に大きく表示される。
4. **Given** アルバムの画面、**When** 写真の並び順を見る、**Then** オーナーが登録した順に、
   左上から右へ向かって並んでいる。
5. **Given** アルバムの画面、**When** アルバムの一覧に戻る操作をする、**Then** アルバムの一覧に戻れる。

---

### User Story 3 - 枚数が多くても待たされない (Priority: P2)

訪問者として、100枚を超えるアルバムでも、最初の表示で長く待たされたくない。スクロールした分だけ
続きが出てくればよい。スマホの回線でも重くないようにしてほしい。

**Why this priority**: 一覧できること自体は User Story 2 で足りるが、全点を一度に読み込むと最初の表示が
遅くなり、流し見という目的が損なわれる。

**Independent Test**: 20枚を超えるアルバムを開いた直後に読み込まれる枚数が限られており、下までスクロール
すると続きが追加されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 20枚を超えるアルバムを開いた直後、**When** 表示されている枚数を数える、**Then** 全点では
   なく決まった件数までしか読み込まれていない。
2. **Given** 一覧の下端までスクロールした状態、**When** そのままスクロールを続ける、**Then** 続きの
   写真が追加で表示される。
3. **Given** 続きの写真が追加された、**When** 追加前から表示されていた写真を見る、**Then** 追加前の
   最後の行より前の写真は、位置が変わっていない(最後の行は、続きの写真と合わせて組み直される)。
4. **Given** すべての写真を表示し終えた状態、**When** さらにスクロールする、**Then** 追加の読み込みは
   行われず、表示も変わらない。
5. **Given** 狭い画面で一覧を見ている、**When** 読み込まれる画像を調べる、**Then** 表示される大きさに
   見合った小さい画像が読み込まれている。

---

### Edge Cases

- 個々の写真が読み込まれるまでの間は、写真と同じ縦横比の場所を確保したプレースホルダを表示し、
  読み込み完了後に写真へ差し替える。表示位置がずれてスクロールが飛ばないようにするため。
- 写真の取得に失敗した場合は、その枠に読み込めなかったことを日本語で示す。他の写真の表示は続ける。
- 画面幅が変わった場合(端末の回転・ウィンドウのリサイズ)は、新しい幅で行が即座に組み直される。
- 画面を開いた直後に、写真が一度並んでから組み直されることがない(表示幅が分かるまでは写真を並べず、
  場所だけを確保する)。
- 1枚だけで表示幅を超える横長の写真(パノラマなど)は、その1枚だけの行にし、表示幅に収まる高さに縮める。
- 存在しないアルバムの URL を開いた場合は、サイト共通の「ページが見つからない」表示になる。
- 公開しているアルバムが1つもない場合は、アルバムの一覧に「まだアルバムがありません」と日本語で示す。
- 20枚以下のアルバムは、最初の表示ですべての写真が並ぶ。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `/other/photograph` は、公開しているアルバムの一覧を表示しなければならない。各アルバムは
  表紙の写真・タイトル・撮影日・枚数を表示し、選ぶとそのアルバムの画面に移らなければならない。
- **FR-002**: アルバムの一覧は、撮影日の新しい順に並べなければならない。
- **FR-003**: アルバムの表紙は、オーナーがそのアルバムの写真から指定した1枚としなければならない。
  指定がなければ、そのアルバムに登録された先頭の写真とする。
- **FR-004**: アルバムの画面は、アルバムのタイトルと撮影日を表示し、アルバムの写真を行ごとに高さを
  揃えたタイル状に並べて表示しなければならない。アルバムの一覧へ戻る導線を持たなければならない。
- **FR-005**: 行の高さの目安は 420px とし、表示幅の半分を超えてはならない(幅375pxの端末では1行に
  2枚前後になる)。
- **FR-006**: 写真は、写真ごとの実際の縦横比で、切り取らずに表示しなければならない。
- **FR-007**: 写真は登録順に左から右へ並べ、目安の高さで並べた幅が表示幅に達したところで行を区切り、
  その行の写真がちょうど表示幅に収まる高さに揃えなければならない。最後の行は目安の高さのまま左に
  寄せる。
- **FR-008**: 初回表示では全点を読み込まず、決まった件数(20件)までを表示しなければならない。
- **FR-009**: 訪問者が一覧の下端付近までスクロールしたときは、続きを同じ件数ずつ追加で表示しなければ
  ならない。追加の前から表示されていた写真のうち、最後の行より前の写真の位置を変えてはならない。
- **FR-010**: すべての写真を表示し終えた後は、追加の読み込みを行ってはならない。
- **FR-011**: 個々の写真は、読み込みが完了するまで、写真と同じ縦横比のプレースホルダで場所を確保
  しなければならない。
- **FR-012**: 写真の取得に失敗した枠には、読み込めなかったことを日本語で示さなければならない。
- **FR-013**: 一覧では、表示される大きさに見合った縮小版の画像を読み込まなければならない。
- **FR-014**: 公開する画像から、撮影情報(撮影場所・撮影機材・撮影日時などの埋め込み情報)を
  取り出せてはならない。
- **FR-015**: 存在しないアルバムの URL に対しては、サイト共通の「ページが見つからない」表示を
  返さなければならない。

### Key Entities *(include if feature involves data)*

- **アルバム**: 写真のまとまり。URL に使う識別子、タイトル、撮影日、登録順に並んだ写真を持つ。
  表紙はオーナーが指定した写真(指定がなければ先頭の写真)。
- **写真**: オーナーが公開している1枚の画像。外部の保管先を指す情報と、幅・高さを持つ。
  同じ写真が複数のアルバムに入ることがある。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 画面を開いてから最初の写真が並ぶまでに、全点の読み込みを待たされない。
- **SC-002**: 下端までスクロールしたとき、続きが表示されるまで操作が止まらない。
- **SC-003**: 幅375px の端末で、横スクロールを発生させずに閲覧できる。
- **SC-004**: 1枚の写真が読み込めなくても、他の写真の閲覧を続けられる。
- **SC-005**: 縦長と横長が混在するアルバムで、最後の行を除く各行の右端が表示幅に揃う。
- **SC-006**: 幅375px の端末で1枚あたりに読み込む画像の大きさが、移行前(約190KB)より小さい。
- **SC-007**: 公開している画像のどれからも、撮影場所・撮影機材・撮影日時を読み取れない。
- **SC-008**: 表示幅 945px のとき、横長の写真だけが並ぶ行の写真1枚の面積が、列の幅を揃える4列表示
  (約225×150px)の2倍以上になる。

## Assumptions

- サイト共通のヘッダー・フッター・配色切替の仕様は [001-home](../001-home/spec.md) で扱い、
  本specでは繰り返さない([ADR-0013](../../docs/adr/0013-spec-per-screen.md))。
- アルバムの詳細画面(`/other/photograph/[album]`)は独立した spec を作らず、本specに含める
  ([ADR-0013](../../docs/adr/0013-spec-per-screen.md))。
- 写真は外部の保管先に置いたものを参照する。サイト側に写真の追加・削除・並べ替えを行う画面は持たない。
  オーナーが写真を選んで公開する手順と保管先は
  [ADR-0017](../../docs/adr/0017-store-photos-in-r2.md) で扱う。
- 既存の写真(移行前の72枚)は、アルバムに振り分けて移す。どのアルバムに入れるかはオーナーが決める。
- 拡大表示、絞り込み、撮影情報(日時・機材)の表示、写真ごとのキャプションは現時点では持たない。
  必要になった時点で本specを更新する(原則1)。
- 似ている写真をどれだけ載せるかはオーナーが公開前に選んで決める。画面側で似た写真をまとめて
  表示することはしない。
