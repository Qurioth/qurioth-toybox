# Quickstart: JSONログ対応・成長チェック一覧・タブ絞り込みの確認手順

**Feature**: [spec.md](./spec.md) / **Plan**: [plan.md](./plan.md)

実装が spec を満たしているかを、実際に動かして確かめる手順。

---

## 前提

- Node.js は [mise.toml](../../mise.toml) の指定に従う(ADR-0010)。依存の取得は pnpm。

```bash
pnpm install
```

- 手元に CCFOLIA から書き出した**同じセッションの HTML ログと JSON ログ**を1組用意する
  (SC-005 の一致確認に使う)。クトゥルフ神話TRPG(7版、`CC` コマンド)のセッションであること。
  実ログは個人のセッション記録なので**リポジトリに置かない**。

## 自動テスト

```bash
pnpm test
```

CI と同じ一式:

```bash
pnpm lint && pnpm format:check && pnpm typecheck && pnpm test && pnpm build
```

## 画面での確認

```bash
pnpm dev
```

`http://localhost:3000/trpg/ccfolia-grep` を開く。

### 1. JSON ログの読み込み(US4)

1. `CCFOLIA LOG FILE` で JSON ログを選ぶ。
2. **期待**: 名前プルダウンに登場人物が並ぶ。タブプルダウンに `すべて` + `main` / `info` /
   各PC名などが並び、`すべて` が選ばれている。形式を聞かれない。
3. 名前を選び `Submit`。**期待**: 結果に `[main] 名前 CC<=30 【回避】 (1D100<=30) … ＞ 失敗`
   のように、コマンドと結果が1行にまとまって出る。

### 2. HTML / JSON の一致(SC-005)

1. 同じセッションの HTML ログを読み込み、同じ名前・同じ成功度で `Submit`。
2. **期待**: 名前一覧、タブ一覧、結果、成長チェック一覧が JSON のときと同じ。
   - HTML のロール行は `コマンド 結果`(半角スペース区切り)。JSON 側はこれに合わせて結合
     している(R2)。

### 3. 成長チェック一覧(US5)

1. JSON ログで探索者を選び `Submit`。
2. **期待**: 2つ目のテキストボックスに `**名前** 成長チェック` と技能名が並ぶ。その下の
   `根拠` に各技能の判定行が1つずつ出る。
3. 目視で照合する(SC-006):
   - `STR` / `DEX` / `POW` / `CON` / `INT` / `アイデア` / `知識` / `幸運` / `正気度ロール` が
     **載っていない**
   - `CC1<=…` `CC2<=…`(ボーナス)の成功だけの技能が**載っていない**
   - `CC-1<=…`(ペナルティ)の成功は**載っている**
   - 同じ技能が2回以上載っていない
   - `【目星】` と `目星` が別々に載っていてもよい(仕様通り)
4. `クトゥルフ神話・信用を除外する` を外して `Submit`。**期待**: それらの成功があれば載る。
5. コピーボタン → Discord に貼る。**期待**: 見出しと等幅囲みの技能名だけが貼られる。

### 4. タブ絞り込み(US6)

1. タブで `main` 以外(例: PC専用タブ)を選び `Submit`。
2. **期待**: 結果と成長チェックがそのタブの行だけになる。名前プルダウンの中身は変わらない。
3. 別のファイルを読み込み直す。**期待**: タブが `すべて` に戻る。

### 5. 壊れないこと(Edge Cases)

- 拡張子 `.json` だが中身が壊れているファイル → 名前・タブが空、エラーは出ない。
- クトゥルフ神話TRPG以外(例: `1d100<=50` だけのログ) → 成長チェックは見出しと空の囲み。
- ファイル未選択で `Submit` → 既存通り `****` の見出しと空の囲み。
