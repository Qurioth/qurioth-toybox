# Feature Specification: リプレイ一覧

**Feature Branch**: `006-replay`

**対象画面**: `/trpg/replay` (`src/app/trpg/replay/page.tsx`)

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "動画・配信で公開しているTRPGリプレイをまとめ、シナリオ名・システム・GM・プレイヤー・キャラクターで探せる画面。限定公開のものはキーワードを入れるまで動画を伏せる。既存実装の現行仕様を spec として書き起こしたもの。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 公開しているリプレイを一覧で見る (Priority: P1)

訪問者として、オーナーが公開しているリプレイ動画をまとめて見たい。どのシナリオを誰と遊んだ
ものかが、動画を再生する前に分かってほしい。

**Why this priority**: この画面の基本。動画とプレイ情報が並ぶこと自体が公開の目的。

**Independent Test**: 画面を開くと、動画とともにシナリオ名・システム・キャラクター・GM・
実施日が並んだカードが表示されることで確認できる。

**Acceptance Scenarios**:

1. **Given** リプレイ一覧を開いた状態、**When** カードを見る、**Then** 動画とともに、シナリオ名・
   TRPGシステム・キャラクター(演じたプレイヤー名を伴う)・GM・実施日が表示される。
2. **Given** 情報が登録されていない項目があるリプレイ、**When** カードを見る、**Then** その項目は
   未設定であることが分かる形で表示される。
3. **Given** 備考が登録されているリプレイ、**When** カードを見る、**Then** 備考が併せて表示される。
   登録が無い場合は備考の欄自体が現れない。

---

### User Story 2 - 条件を指定して目的のリプレイを探す (Priority: P1)

訪問者として、特定のGM・プレイヤー・システム・シナリオのリプレイだけを見たい。本数が増えると
一覧を上から辿るのが現実的でなくなるため。

**Why this priority**: 本数が増えるほど価値が上がる。一覧できることと同じくらい重要。

**Independent Test**: 検索欄に語を入れると一致するものだけが残り、候補から項目を指定すると
その項目の値だけで絞り込めることで確認できる。

**Acceptance Scenarios**:

1. **Given** リプレイ一覧、**When** 検索欄に語を入力する、**Then** シナリオ名・システム・GM・
   プレイヤー・キャラクターのいずれかにその語を含むものだけが残る。空白で区切って複数の語を
   入力した場合は、すべてを含むものだけが残る。
2. **Given** 検索欄に入力している状態、**When** 表示された候補を選ぶ、**Then** その項目と値の
   組が絞り込み条件として追加され、検索欄の入力は消える。
3. **Given** 絞り込み条件が追加されている状態、**When** 条件の削除操作を行う、**Then** その条件
   だけが外れ、他の条件は残る。
4. **Given** 絞り込みを行っている状態、**When** 件数表示を見る、**Then** 「一致件数 / 全件数」が
   示される。
5. **Given** 条件に一致するリプレイが無い状態、**When** 一覧を見る、**Then** 一致するものがない
   旨が日本語で示される。

---

### User Story 3 - 限定公開のリプレイを開く (Priority: P2)

シナリオのネタバレを避けたい訪問者・オーナーとして、未プレイの人の目に不用意に触れてほしく
ないリプレイは、内容を知っている人だけが開けるようにしたい。

**Why this priority**: 対象は一部のリプレイに限られるが、この配慮が無いと公開自体を
ためらうことになる。

**Independent Test**: 限定公開のリプレイでは動画の代わりにキーワードの入力欄が表示され、
正しいキーワードを入れると動画が現れることで確認できる。

**Acceptance Scenarios**:

1. **Given** 限定公開のリプレイ、**When** カードを見る、**Then** 動画の代わりに、限定公開である
   ことの説明とキーワードの入力欄が表示される。
2. **Given** 限定公開のリプレイのキーワード入力欄、**When** 正しいキーワードを入力して実行する、
   **Then** 動画が表示される。大文字・小文字や前後の空白の違いは区別されない。
3. **Given** 限定公開のリプレイのキーワード入力欄、**When** 誤ったキーワードを入力して実行する、
   **Then** 一致しない旨が日本語で示され、動画は表示されない。
4. **Given** 限定公開ではないリプレイ、**When** カードを見る、**Then** キーワードを求められずに
   動画が表示される。

---

### Edge Cases

- 一覧は一度にすべてを表示せず、決まった件数ずつ読み込む。下端に近づくと続きが追加される。
- すべて表示し終えた後は、その旨が示され、追加の読み込みは行われない。
- 絞り込みの条件を変えたときは、表示件数が最初の1回分に戻る。前の条件で読み進めた位置を
  引き継がないようにするため。
- 検索欄に項目名を指定する書き方(例: 「GM名:」に続けて値)を用いた場合も、候補から選んだ場合と
  同じ絞り込みになる。
- 同じ絞り込み条件を重ねて追加しても、条件は増えない。
- 動画ではなく再生リストとして公開しているリプレイも、同じカードの形式で扱う。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 一覧は、公開しているリプレイをカード形式で並べ、動画(または再生リスト)と、
  シナリオ名・TRPGシステム・キャラクター・GM・実施日・備考を表示しなければならない。
- **FR-002**: キャラクターは、演じたプレイヤー名が登録されている場合、キャラクター名と併せて
  表示しなければならない。
- **FR-003**: 登録の無い項目は、未設定であることが分かる形で表示しなければならない。ただし
  備考は登録が無い場合、欄そのものを表示してはならない。
- **FR-004**: 検索欄への入力は、シナリオ名・システム・GM・プレイヤー・キャラクターを対象とし、
  空白で区切った語をすべて含むものだけを残さなければならない。
- **FR-005**: 入力に応じて、項目と値の組を絞り込み条件の候補として提示しなければならない。
- **FR-006**: 候補を選んだ場合、その項目と値の組を絞り込み条件として追加し、検索欄の入力を
  空にしなければならない。同じ条件を重ねて追加してはならない。
- **FR-007**: 追加した絞り込み条件は個別に解除でき、すべてを一度に解除する操作も提供しなければ
  ならない。
- **FR-008**: 一覧は「一致件数 / 全件数」を常に表示しなければならない。
- **FR-009**: 条件に一致するリプレイが無い場合は、その旨を日本語で示さなければならない。
- **FR-010**: 一覧は一度に全件を表示せず、決まった件数(10件)ずつ表示し、下端に近づいたときに
  続きを追加しなければならない。すべて表示し終えた後は追加してはならない。
- **FR-011**: 絞り込みの条件が変わったときは、表示件数を最初の1回分に戻さなければならない。
- **FR-012**: 限定公開に設定されたリプレイは、正しいキーワードが入力されるまで動画を表示しては
  ならない。代わりに、限定公開である旨の説明とキーワードの入力欄を表示しなければならない。
- **FR-013**: キーワードの照合では、大文字・小文字の違いと前後の空白を無視しなければならない。
  一致しない場合はその旨を日本語で示さなければならない。

### Key Entities *(include if feature involves data)*

- **リプレイ**: 公開している1本の動画または再生リスト。動画または再生リストの識別子、TRPG
  システム名、シナリオ名、キャラクター(キャラクター名と任意のプレイヤー名)、GM名、実施日、
  備考、限定公開のキーワードを持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 訪問者が、特定のGM・プレイヤー・システムのリプレイだけを2操作以内で絞り込める。
- **SC-002**: 本数が増えても、画面を開いた直後の表示で待たされない。
- **SC-003**: 動画を再生する前に、どのシナリオを誰と遊んだものかを判断できる。
- **SC-004**: 限定公開のリプレイの内容が、キーワードを知らない訪問者の目に触れない。

## Assumptions

- サイト共通のヘッダー・フッター・配色切替の仕様は [001-home](../001-home/spec.md) で扱い、
  本specでは繰り返さない([ADR-0013](../../docs/adr/0013-spec-per-screen.md))。
- 動画は外部の動画共有サービスに置いたものを埋め込む。当サイトは動画そのものを持たない。
- リプレイの情報はリポジトリ内のデータとして持ち、画面から投稿・編集はできない。
- 限定公開のキーワードは「未プレイの人が偶然ネタバレに触れること」を防ぐための仕切りであり、
  機密を守る仕組みではない。秘匿が必要な内容は、そもそも公開しない前提とする。
- 並べ替えの操作は持たない。並び順はデータの登録順に従う(原則1)。
- 本specは既存実装の現行仕様を書き起こしたものであり、新機能の追加を含まない。
