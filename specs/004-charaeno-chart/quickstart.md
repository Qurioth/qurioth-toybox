# Quickstart: 6版のキャラクターシート対応の確認手順

**Feature**: [spec.md](./spec.md) / **Plan**: [plan.md](./plan.md)

実装が spec を満たしているかを、実際に動かして確かめる手順。実装の中身ではなく
「何をどう確認するか」を書く。

---

## 前提

- Node.js は [mise.toml](../../mise.toml) の指定に従う(ADR-0010)。
- 依存の取得は pnpm(Corepack 経由)。

```bash
pnpm install
```

- 6版の確認には、Charaeno に保管した**6版のキャラクターシートのURL**が1つ必要
  (`https://charaeno.com/6th/...` の形)。7版のURLも1つ用意しておくと退行確認が楽。
- 外部サービスへ接続するため、ネットワークが必要。

## 自動テスト

```bash
pnpm test
```

CI と同じ一式を通す場合:

```bash
pnpm lint && pnpm format:check && pnpm typecheck && pnpm test && pnpm build
```

**期待**: 既存のテストがすべて通り、6版まわりの追加分も通る。
[research.md](./research.md) R9 の表が、どのファイルに何が増えるかの一覧。

## 画面での確認

```bash
pnpm dev
```

`http://localhost:3000/trpg/charaeno-chart` を開く。

### シナリオ1: 6版のシートでカードが出る(FR-002 / FR-012 / FR-013、US2-1)

1. 入力欄に6版のシートURLを貼る。
2. Submit を押す。

**期待**: 版を選ぶ操作を求められずにカードが表示される。ブラウザの開発者ツールの
Network で、取得先が `/api/v1/6th/{id}/summary` になっていること(`7th` になっていない)。

### シナリオ2: 6版のレーダーチャートが読める(FR-017、US2-2)

**期待**: 8つの能力値がチャートの中心付近に潰れておらず、高い能力値と低い能力値の差が
形として分かる。EDU は 21、それ以外は 18 を上限とした割合で描かれている。

> 目安: EDU 15 の探索者なら EDU の頂点は外周の約 7 割の位置。同じ 15 でも INT なら
> 18 が上限なので約 8 割まで伸びる。両者の見え方が違えば、能力値ごとの上限が効いている。

### シナリオ3: 6版の表面は HP・MP・SAN・DB(FR-014、US2-3)

**期待**: 表面の数値タイルが HP・MP・SAN・DB の4つで、幸運が無い。DB は「+0」「+1D4」のように
取得した表記のまま出る(数値に化けたり空になったりしない)。デスクトップ幅・モバイル幅の
どちらでも枠がはみ出さない。

### シナリオ4: 6版の裏面(FR-015 / FR-016、US3-4)

デスクトップ幅(768px 以上)でカードをクリック、またはカードにフォーカスして Enter / Space。

**期待**:

- 技能表に、既定値から変更された技能だけが並ぶ。
- 設定欄が「精神的な障害 → 読んだクトゥルフ神話の魔導書 → アーティファクト／学んだ呪文 →
  メモ」の順で並ぶ。
- 記入の無い項目は見出しごと出ない。
- 住所・描写・家族＆友人・狂気の症状・負傷・傷跡・遭遇した超自然の存在・所持品・武器・財産・
  チャットパレットは**出ない**。

モバイル幅(768px 未満)では表裏の区別がなく、同じ内容が縦に並ぶ。

### シナリオ5: 7版が変わっていない(SC-006、US2-4)

1. 7版のシートURLで同じ手順を踏む。

**期待**: 対応前と同じカード。表面は HP・MP・SAN・幸運の4つ、裏面はバックストーリー10項目と
メモ。チャートの形も変わらない。

### シナリオ6: 対応外のURL(FR-002、US1-4)

`https://charaeno.com/8th/abc123` のような対応外の版を入力して Submit。

**期待**: 「URLの形式が不正です。」が出て、取得は行われない(Network にリクエストが出ない)。

### シナリオ7: 失敗時の扱い(FR-006 / FR-007)

1. 実在しないIDの6版URL(例: `https://charaeno.com/6th/does-not-exist`)を入力して Submit。

**期待**: 「キャラクターシートを取得できませんでした。…」が出る。直前にカードが出ていた場合、
そのカードは消えている。

### シナリオ8: サンプル一覧が変わっていない

`http://localhost:3000/trpg/charaeno-chart/sample-character` を開く。

**期待**: 従来どおり7版のサンプルが並び、表裏の切り替えも動く。6版のサンプルは増えていない。
表面のタイルは HP・MP・SAN・幸運の4つのまま。

### シナリオ9: 入口のカードが「7版のみ」に見えない

`http://localhost:3000/trpg` を開く。

**期待**: Charaeno Chart Card の対応システムが「クトゥルフ神話TRPG」になっている
(「7版」が付いていない)。この画面の仕様は [002-trpg](../002-trpg/spec.md) 側にある。

## 詰まったら

| 症状 | 見るところ |
|---|---|
| 6版で必ず「形式が想定と異なります」 | 版ごとの型ガードが分かれているか。7版固有の項目(`backstory` / `attribute.luck`)を6版に要求していないか。逆に6版が要求する `attribute.db` がレスポンスにあるか([data-model.md](./data-model.md) 3節) |
| 6版のチャートが中心に潰れる | 能力値の正規化が入っているか。上限が 100 のままになっていないか([research.md](./research.md) R1) |
| 7版のチャートの形が変わった | 7版の上限が 100 になっているか。正規化で丸めが効きすぎていないか |
| 6版なのに7版の内容を取ってくる | 検証用の正規表現と取得先の組み立てで版が共有されているか([contracts/charaeno-summary-api.md](./contracts/charaeno-summary-api.md) 2節) |
