# Feature Specification: つながり管理表

**Feature Branch**: `007-connection-table`

**対象画面**: `/trpg/connection-table` (`src/app/trpg/connection-table/page.tsx`)

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "「ふしぎもののけRPG ゆうやけこやけ」のコネクション(つながり)をセッション中に記録する表。参加者どうしのつながりの内容と強さを入力し、行と列の合計を自動で出す。既存実装の現行仕様を spec として書き起こしたもの。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 卓の顔ぶれを表にする (Priority: P1)

GMまたはプレイヤーとして、その日の卓に参加する人数に合わせて表の行を用意したい。人数は卓ごとに
違うため、決め打ちの人数では使えない。

**Why this priority**: 表の形が卓に合わないと、以降の記入が始まらない。

**Independent Test**: 画面を開いた状態から行を追加・削除でき、参加者の名前を書き換えられる
ことで確認できる。

**Acceptance Scenarios**:

1. **Given** 画面を開いた直後、**When** 表を見る、**Then** 「町」と、名前が未記入の参加者の行が
   あらかじめ用意されている。
2. **Given** 表を表示している状態、**When** 行の追加操作を行う、**Then** 参加者の行が1つ増え、
   既存の全参加者との組み合わせが表に加わる。
3. **Given** 参加者の行がある状態、**When** その行の削除操作を行う、**Then** その参加者の行と列、
   および関係する記入内容がまとめて表から消える。
4. **Given** 表を表示している状態、**When** 「町」の行の名前を変更または削除しようとする、
   **Then** 変更も削除もできない。

---

### User Story 2 - つながりを記録して合計を見る (Priority: P1)

プレイヤーとして、誰から誰へ、どんなつながりを、どれくらいの強さで持っているかを記録し、
合計を自動で出したい。セッション中に暗算したくないため。

**Why this priority**: この表の中心的な価値。合計を手計算するなら紙で足りてしまう。

**Independent Test**: 各セルにつながりの内容と強さを入力すると、行と列の合計がその場で
更新されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 表のセル、**When** つながりの内容を入力する、**Then** 入力した内容がそのセルに
   記録される。入力の際は、このゲームでよく使う内容が候補として提示される。
2. **Given** 表のセル、**When** つながりの強さに1から5の値を入力する、**Then** その値が記録され、
   行と列の合計が即座に更新される。
3. **Given** 表のセル、**When** つながりの強さに1から5以外の値を入力する、**Then** その入力は
   記録されない。
4. **Given** 記入済みの表、**When** 行の合計を見る、**Then** その参加者が他の全員へ向けている
   強さの合計が表示される。
5. **Given** 記入済みの表、**When** 列の合計を見る、**Then** その参加者が他の全員から向けられて
   いる強さの合計が表示される。
6. **Given** 「町」から参加者へのセル、**When** 内容を変更しようとする、**Then** 内容は固定の
   ままで変更できず、強さだけを入力できる。
7. **Given** 参加者自身への対角のセル、**When** セルを見る、**Then** 入力欄が無く、記入できない。

---

### User Story 3 - 続きから使う (Priority: P2)

同じキャンペーンを続けているプレイヤーとして、前回入力した内容を次回もそのまま使いたい。
毎回入力し直すのは現実的でないため。

**Why this priority**: 単発の卓なら無くても足りるが、継続する卓では入力量がそのまま負担に
なる。

**Independent Test**: 入力した後にブラウザを閉じて開き直しても、入力内容が残っていることで
確認できる。

**Acceptance Scenarios**:

1. **Given** 表に入力した状態、**When** 画面を離れて後から同じ環境で開き直す、**Then** 参加者と
   つながりの記入内容が復元される。
2. **Given** 保存された内容が読み取れない状態、**When** 画面を開く、**Then** 画面は壊れず、
   初期状態の表が表示される。

---

### Edge Cases

- 名前が未記入の行が複数あっても、行を取り違えずに操作・読み上げできるよう、行番号で区別する。
- 参加者の数が多く表が画面幅に収まらない場合は、表の内側だけを横にスクロールし、画面全体を
  横スクロールさせない。
- 保存されていた内容が壊れている、または想定の形を満たさない場合は、その内容を捨てて初期状態に
  戻す。
- 参加者を削除した場合、その参加者に向けたつながり・その参加者からのつながりの双方が消え、
  合計に残らない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 表は、行(つながりを向ける側)と列(向けられる側)で参加者を突き合わせた
  一方向のつながりを記録できなければならない。
- **FR-002**: 画面を開いた直後は、「町」と、名前が未記入の参加者があらかじめ用意されて
  いなければならない。
- **FR-003**: 利用者は、参加者の行を追加・削除できなければならない。「町」の行は削除しては
  ならない。
- **FR-004**: 利用者は、参加者の名前を編集できなければならない。「町」の名前は編集しては
  ならない。
- **FR-005**: 参加者を削除したときは、その参加者に関わるつながりの記入内容をすべて取り除かな
  ければならない。
- **FR-006**: つながりの内容の入力時には、このゲームでよく使う内容を候補として提示しなければ
  ならない。候補以外の内容も入力できなければならない。
- **FR-007**: つながりの強さは1から5の範囲でのみ記録しなければならない。範囲外の入力は記録
  してはならない。未入力の状態も許容しなければならない。
- **FR-008**: 「町」から参加者へ向けたつながりの内容は固定とし、変更できてはならない。強さは
  入力できなければならない。
- **FR-009**: 参加者自身へ向けたセルには、入力欄を設けてはならない。
- **FR-010**: 各行には、その参加者が他の全員へ向けている強さの合計を表示しなければならない。
- **FR-011**: 各列には、その参加者が他の全員から向けられている強さの合計を表示しなければ
  ならない。
- **FR-012**: 合計は、記入内容が変わったときに即座に更新されなければならない。
- **FR-013**: 入力内容は利用者の環境に自動で保存し、次に同じ環境で開いたときに復元しなければ
  ならない。保存操作を利用者に求めてはならない。
- **FR-014**: 保存された内容が読み取れない場合は、その内容を捨てて初期状態を表示しなければ
  ならない。
- **FR-015**: 名前が未記入の行も、行番号によって他の行と区別できなければならない。
- **FR-016**: 表が画面幅に収まらない場合は、表の内側だけを横にスクロールできなければならない。

### Key Entities *(include if feature involves data)*

- **参加者**: 表の1行および1列にあたる対象。識別子と名前を持つ。「町」は常に存在する特別な
  参加者で、名前の編集と削除ができない。
- **つながり**: ある参加者から別の参加者へ向けた関係。内容(好意・信頼などの言葉)と強さ
  (1から5、または未入力)を持つ。向きが異なれば別のつながりとして扱う。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: セッション中に、卓の人数に合わせた表を作るまで1分以内で準備できる。
- **SC-002**: つながりの強さを入力してから合計が更新されるまで、利用者が待たされない。
- **SC-003**: 保存操作を一度も行わずに、次回同じ環境で開いたときに前回の内容が残っている。
- **SC-004**: 参加者が6人を超えても、表の内側の横スクロールだけで全セルに到達できる。

## Assumptions

- サイト共通のヘッダー・フッター・配色切替の仕様は [001-home](../001-home/spec.md) で扱い、
  本specでは繰り返さない([ADR-0013](../../docs/adr/0013-spec-per-screen.md))。
- 対象は「ふしぎもののけRPG ゆうやけこやけ」のつながりの記録のみ。他システムの人間関係表には
  対応しない。
- 入力内容は利用者の手元にのみ保存し、サーバーへは送信しない。したがって別の端末やブラウザとは
  共有されず、閲覧データを消すと失われる。
- 複数人で同時に編集する用途は想定しない。表は1人が代表して記入する前提とする(原則1)。
- 記入内容の書き出し・読み込み、履歴の保持は持たない。必要になった時点で本specを更新する。
- 本specは既存実装の現行仕様を書き起こしたものであり、新機能の追加を含まない。
