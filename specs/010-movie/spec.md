# Feature Specification: 動画一覧

**Feature Branch**: `010-movie`

**対象画面**: `/other/movie` (`src/app/other/movie/page.tsx`)

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "旅行などでオーナーが撮影した動画(YouTube にアップロード済み)をまとめて見られる画面を `/other` 配下に新規作成する。動画ごとにプレーヤーを埋め込み、タイトル・撮影場所・撮影日・メモを添える。新しく撮影したものほど上に並べ、`/other` に Movie の区分を追加して辿れるようにする。検索・絞り込み、キーワードで開く限定公開、投稿機能は含めない。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 旅先で撮った動画を眺める (Priority: P1)

訪問者として、オーナーが旅行などで撮った動画を一か所でまとめて見たい。動画サイトのチャンネルを
探しに行かなくても、このサイトの中でそのまま再生できてほしい。

**Why this priority**: この画面の唯一の目的。動画が並び、その場で再生できること自体が価値になる。
写真一覧([009-photograph](../009-photograph/spec.md))と対になる、オーナーの個人コンテンツの
置き場でもある。

**Independent Test**: `/other/movie` を開き、登録した動画が新しい順に並び、それぞれをページを
離れずに再生できることで確認できる。

**Acceptance Scenarios**:

1. **Given** 動画が登録されている状態、**When** `/other/movie` を開く、**Then** 動画ごとに、
   ページ内で再生できるプレーヤーとタイトルが表示される。
2. **Given** 一覧に並んだ動画、**When** プレーヤーの再生操作を行う、**Then** 画面を移動せずに
   その場で動画が再生される。
3. **Given** 撮影日の異なる動画が複数登録されている状態、**When** 一覧を見る、**Then** 撮影日の
   新しいものほど上に並ぶ。
4. **Given** 動画が1本も登録されていない状態、**When** `/other/movie` を開く、**Then** 公開して
   いる動画がまだ無い旨が日本語で示される。

---

### User Story 2 - どこでいつ撮った動画かを知る (Priority: P2)

訪問者として、再生する前に、その動画がどこでいつ撮ったものかを知りたい。旅先の思い出として
見るので、場所と時期が分かると選びやすい。

**Why this priority**: 動画を並べるだけでも User Story 1 は成り立つが、本数が増えると何の動画か
分からないまま再生することになる。添える情報があって初めて「流し見」がしやすくなる。

**Independent Test**: 撮影場所・撮影日・メモを登録した動画と、一部を登録していない動画を並べ、
登録した項目だけが表示されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 撮影場所・撮影日・メモがすべて登録された動画、**When** 一覧を見る、**Then**
   タイトルとともに撮影場所・撮影日・メモが表示される。
2. **Given** 撮影場所・撮影日・メモのいずれかが登録されていない動画、**When** 一覧を見る、
   **Then** 登録されていない項目は欄ごと表示されず、「未設定」などの表記も出ない。
3. **Given** 複数行にわたるメモが登録された動画、**When** 一覧を見る、**Then** メモの全文が
   読める形で表示される。

---

### User Story 3 - `/other` から動画一覧へ移動する (Priority: P2)

訪問者として、ヘッダーの OTHER から動画一覧に辿り着きたい。写真と同じように、区分を見れば
動画が置かれていることが分かってほしい。

**Why this priority**: 導線が無いと画面が存在していても見つけてもらえない
([constitution.md](../../.specify/memory/constitution.md) 原則2)。ただし画面そのものの価値は
User Story 1 にあるため P2 とする。

**Independent Test**: `/other` に Movie の区分が見出しと入口の形で表示され、入口を選ぶと
`/other/movie` へ遷移することで確認できる。

**Acceptance Scenarios**:

1. **Given** `/other` を表示している状態、**When** 画面を見る、**Then** 写真の区分と同じ形式で
   Movie の区分(見出しと入口)が表示される。
2. **Given** `/other` を表示している状態、**When** Movie の入口を選ぶ、**Then** 動画一覧画面へ
   遷移する。

---

### Edge Cases

- 動画の本数が増えても、画面を開いた直後にすべての動画のプレーヤーを読み込まない。画面に
  表示される付近のものから読み込み、スクロールに応じて続きを読み込む。
- 読み込み前のプレーヤーの位置には、動画と同じ縦横比の枠をあらかじめ確保しておく。読み込みに
  よって表示位置がずれ、スクロールが飛ばないようにするため。
- 撮影日が同じ動画が複数ある場合は、データに登録した順に並べる。
- 撮影日が登録されていない動画は、撮影日のある動画すべての後ろに、登録した順で並べる。
- 動画サイト側で削除・非公開にされた動画は、そのプレーヤーの中で再生できない旨が示されれば
  よい。他の動画の表示・再生は妨げない。
- 縦長に撮影した動画も、他の動画と同じ横長の枠の中に表示する(枠の左右に余白ができる)。
- タイトルやメモが長い場合も、画面幅の内側で折り返して表示し、横スクロールを発生させない。
- 画面幅が狭い環境では、動画は1列に並び、画面幅いっぱいに広がる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 本画面は、オーナーが登録した動画を一覧として表示し、動画ごとにページ内で再生
  できるプレーヤーを表示しなければならない。
- **FR-002**: 動画ごとに、タイトルを表示しなければならない。
- **FR-003**: 動画ごとに、撮影場所・撮影日・メモが登録されている場合はそれを表示しなければ
  ならない。登録されていない項目は、欄そのものを表示してはならない。
- **FR-004**: 一覧は、撮影日の新しいものから順に並べなければならない。撮影日が同じもの同士は
  登録順に、撮影日の無いものは撮影日のあるものの後ろに登録順で並べなければならない。
- **FR-005**: 登録されている動画が1本も無い場合は、その旨を日本語で示さなければならない。
- **FR-006**: 画面を開いた直後にすべての動画のプレーヤーを読み込んではならない。表示範囲に
  近づいた動画から順に読み込まなければならない。
- **FR-007**: 読み込み前のプレーヤーの位置には、読み込み後と同じ大きさの領域を確保しなければ
  ならない。
- **FR-008**: `/other` には、写真の区分と同じ形式で Movie の区分(見出しと入口)を表示し、
  入口から本画面へ遷移できなければならない([008-other](../008-other/spec.md) を併せて更新する)。
- **FR-009**: 画面上の文言は日本語で表示しなければならない(区分名の「Movie」など、既存の
  見出しの表記に合わせた英語の見出しを除く)。

### Key Entities *(include if feature involves data)*

- **動画**: オーナーが撮影し、外部の動画共有サービスで公開している1本の動画。動画の識別子、
  タイトル(必須)、撮影場所・撮影日・メモ(いずれも任意)を持つ。掲載内容はオーナーがデータを
  書き足して更新する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ヘッダーの OTHER を選んでから1操作で動画一覧に到達できる。
- **SC-002**: 訪問者が、動画を再生する前に、その動画のタイトルと(登録されていれば)撮影場所・
  撮影日を確認できる。
- **SC-003**: 動画の本数が増えても、画面を開いてから最初の動画が見えるまでの待ち時間が、
  動画1本だけのときと体感で変わらない。
- **SC-004**: 幅375px の端末で、横スクロールを発生させずに全内容を閲覧・再生できる。
- **SC-005**: オーナーが動画を1本追加するとき、データに1件書き足すだけで一覧に反映される。

## Assumptions

- サイト共通のヘッダー・フッター・配色切替の仕様は [001-home](../001-home/spec.md) で扱い、
  本specでは繰り返さない([ADR-0013](../../docs/adr/0013-spec-per-screen.md))。
- 掲載する動画はすべてオーナー本人が撮影し、外部の動画共有サービスに公開(または限定公開)
  したもの。当サイトは動画そのものを持たず、埋め込んで再生する。
- 対象は単体の動画のみとし、再生リストは扱わない。必要になった時点で本specを更新する(原則1)。
- 動画の追加・修正はリポジトリ内のデータを書き換えて行い、画面から投稿・編集する機能は持たない。
- TRPGのリプレイ一覧([006-replay](../006-replay/spec.md))とは別のコンテンツとして扱い、
  データも共有しない。
- 検索・絞り込み、並べ替えの操作、キーワード入力で開く限定公開の仕組み、コメントや評価などの
  投稿機能は持たない。本数が増えて必要になった時点で本specを更新する(原則1)。
- 撮影日は日付の単位で登録する。時刻は扱わない。
