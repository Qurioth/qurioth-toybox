# Contract: シナリオ詳細画面の振る舞い

`/trpg/scenario/<シナリオID>` が訪問者に対して保証する振る舞い。結合テスト
(React Testing Library)とquickstartの確認項目は、この契約を基準にする。

## 1. 表示形式の切り替え

| 条件 | 表示 |
| -- | -- |
| ID が登録されていて `structured: true` | 構造化表示(2〜5) |
| ID が登録されていて `structured` なし | 従来の整形表示(現行と同一) |
| ID が登録されていない | 従来の整形表示で本文が空。画面は壊れない。タブの名称はサイトの既定 |

どの形式でも、次の 3 点は変わらない。

- URL は `/trpg/scenario/<シナリオID>` のまま。一覧のカードから 1 操作で開ける。
- `system` にクトゥルフ神話TRPGを含む場合は、末尾に二次創作表記・権利表記が付く。
- タブの名称はシナリオのタイトル。

## 2. 冒頭の概要(構造化表示)

本文より前に、次をひとまとまりで表示する。

- サブタイトル(ある場合)、タイトル
- 対応システム(`system`)、対応人数、想定プレイ時間。一覧カードと同じ表記にする。
  上限と下限が同じなら単一の値で表示する。
- 概要リード(舞台・前提。本文の H1 直後の段落)

## 3. 目次(構造化表示)

- 項目: 全章(`##`)。章の下に、その章の人物・エンディング・その他報酬を入れ子で並べる。
- 項目はページ内リンク。選ぶとその見出しへ移動し、見出しは固定ヘッダーに隠れない。
- 幅 `lg` 以上: 本文の横に常に表示され、スクロールしても見えている。
- 幅 `lg` 未満: 画面右下の「目次」ボタンで開くパネルとして表示する。項目を選ぶとパネルが閉じて
  移動する。閉じたパネルは本文に重ならない(ボタンだけが残る)。
- アクセシビリティ: 目次は `nav` 要素で、名前は「目次」。パネルを開くボタンは
  `aria-expanded` を持つ。

## 4. 本文(構造化表示)

- 章は本文の出現順に並べる。見出しはすべて展開した状態で表示し、折りたたまない。
- 人物はカードで表示する。カードの中は、立ち絵、見出し(補足付き)、プロフィール、
  `####` の区画の順。`####` の区画は本文の出現順のまま並べる。
- 能力値は「項目名と値」の組を格子状に並べる。幅 375px でも横スクロールしない。
- 判定・正気度喪失・正気度回復・呪文・魔導書/アーティファクト・出典は、それぞれ見分けの
  つく見た目にする([structured-markdown.md](structured-markdown.md) 4 章)。色だけに頼らず、
  枠や記号の形でも区別できるようにする。
- 作中テキストは枠付きで改行を保つ。セリフは 1 行ずつ区切る。
- 読み上げ文は枠で囲み、作中テキスト・セリフ・地の文のいずれとも見分けられる見た目にする。
  目印(`[!読み上げ]`)は表示しない。中の改行と、判定などの強調は保つ。
- エンディングは「ED<番号>」と名称を分けて見出しにする。その他報酬は別の見た目にする。
- 表は表単体で横スクロールでき、ページ全体には横スクロールを発生させない。
- ダークモードでも、上記の区別がすべて読み取れる。
