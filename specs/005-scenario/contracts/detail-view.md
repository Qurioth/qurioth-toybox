# Contract: シナリオ詳細画面の振る舞い

`/trpg/scenario/<シナリオID>` が訪問者に対して保証する振る舞い。結合テスト(React Testing Library)と
quickstart の確認項目は、この契約を基準にする。

## 1. 表示形式の切り替え

| 条件 | 表示 |
| -- | -- |
| ID が登録されていて `page` がある | 専用ページ(`src/scenarios/<slug>/index.tsx`) |
| ID が登録されていて `markdown` がある | 従来の整形表示(2026-10-02 以前と同一) |
| ID が登録されていない | 従来の整形表示で本文が空。画面は壊れない。タブの名称はサイトの既定 |

どの形式でも、次の点は変わらない(詳細画面 `[id]/page.tsx` が担う)。

- URL は `/trpg/scenario/<シナリオID>` のまま。一覧のカードから 1 操作で開ける。
- `system` にクトゥルフ神話TRPGを含む場合は、末尾に二次創作表記・権利表記が付く。
- タブの名称はシナリオのタイトル。
- 専用ページの部品(`ScenarioOverview` など)は、登録情報(タイトル・システム・人数・時間)を
  詳細画面から受け取る。ページ側で同じ情報を書き写さない。

## 2. 専用ページ

- 見た目はページごとに異なってよい。あるページの配色・レイアウトが、他のシナリオの表示に影響しない
  (スタイルはページの要素の中に閉じる。グローバルな CSS をページから足さない)。
- 部品の振る舞いは [mdx-page.md](mdx-page.md) 3 章のとおり。どのページに置いても同じように動く。

## 3. 目次(`ScenarioToc` を置いたページ)

- 項目: 本文の `h2` と、`data-toc` 付きの見出し(NPC カード、ED、その他報酬など)。`h2` の下に、
  次の `h2` までの `data-toc` 見出しを入れ子で並べる。
- 項目を選ぶとその見出しへ移動し、見出しは固定ヘッダーに隠れない。
- 幅 `lg` 以上: 本文の横に常に表示され、スクロールしても見えている。
- 幅 `lg` 未満: 画面右下の「目次」ボタンで開くパネルとして表示する。項目を選ぶとパネルが閉じて移動する。
- 目次は `nav` 要素で、名前は「目次」。パネルを開くボタンは `aria-expanded` を持つ。

### 右の列(`ScenarioPage` の `aside`)

- 幅 `xl` 以上: 本文の右に常に表示し、スクロールしても見えている。
- 幅 `xl` 未満: 本文の流れには置かず、画面右下の「<見出し>」ボタンで開くパネルとして表示する。
  目次のボタンもある幅(`lg` 未満)では、目次のボタンの上に並べる。ボタンは `aria-expanded` を持つ。

## 4. NPC カードと CCFOLIA

- カードは `article` 要素で、名前は NPC の名前。
- 立ち絵は名前の左に、顔の辺りを丸く切り抜いたアイコン(幅 `sm` 以上で 88px、未満で 64px)で出す。
  能力値・技能の有無にかかわらず、どの人物も同じ見え方にする。立ち絵が無ければアイコンを出さない。
- アイコンには既定で画像の幅いっぱいを映し、上から少し下(全身の立ち絵なら頭から胸元)を見せる。
  人物データの `portrait.face` を書くと、映す範囲を顔に寄せるなど変えられる。
- アイコンを選ぶと、立ち絵の全体を切り抜かずに縦横比を保って開く。ダイアログは画面に収まる大きさで
  スクロールせず、幅を画像に揃える(図の拡大とは異なり、原寸にはしない)。
- 能力値・技能・子要素(プロフィールやセリフ例など)は、この順で名前の下にカードの幅いっぱいで並べる。
- 能力値は「項目名と値」の組を格子状に並べ、幅 375px でも横スクロールしない。
- 「CCFOLIA コマ出力」ボタンで [ccfolia-koma.md](ccfolia-koma.md) の JSON をクリップボードに書き込み、
  結果を日本語で示す。

## 5. 図とフローチャート

- 図はキャプション付きで表示し、選ぶと原寸の画像をダイアログで開く。ダイアログの中ではスクロール
  して細部を読める。閉じるボタンと Esc で閉じられる。
- フローチャートは、図が画面より大きい場合に図の枠の中だけでスクロールする。ページ全体には横
  スクロールを出さない。ダークモードでは図の配色も暗い背景用に切り替わる。
