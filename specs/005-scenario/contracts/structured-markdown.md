# Contract: 構造化表示が前提とする本文 Markdown

構造化表示(`structured: true`)に移行するシナリオの本文が満たすべき条件。
[シナリオ本文の記述規約](../../../src/data/scenario/README.md)(ADR-0014)のうち、解釈の結果を
左右する部分を抜き出して、構造化表示側の扱いを明記したもの。ここに書いていない規約(数値と
記号の間の空白など)は表示に影響しない。

移行作業では、この条件を満たすよう本文を整える。満たしていない記述も消えはしないが、
汎用の見た目で表示される。

## 1. 見出し

| 条件 | 構造化表示での扱い | 満たさない場合 |
| -- | -- | -- |
| 見出しは ATX 形式(`#` 始まり)で書く | 区画の区切りになる | Setext 形式は見出しとして扱われない |
| H1 は 1 つだけ。H1 の前に置けるのはサブタイトルの斜体 1 行のみ | タイトル・サブタイトルとして冒頭の概要に出る | 2 つ目以降の H1 は本文中の文字列として扱われる |
| `##` の固定セクション名は規約どおりに書く(`GM 向け情報` `特殊 HO` `推奨技能` `主な NPC` `シナリオの導入` `クライマックス` `シナリオ終了`) | 章の種別が決まる | 場面(`scene`)として扱われる(例: `シナリオ終了報酬` は ED の見た目にならない) |
| 章は規約 2 章の順に並べる | 本文の出現順で表示する(並べ替えない) | データ適合テストが失敗する |
| `GM 向け情報` `主な NPC` `シナリオの導入` `シナリオ終了` の章を持つ(`クライマックス` は任意) | — | データ適合テストが失敗する |
| フェンス付きコードブロック内の `#` 行 | 見出しとして扱わない | — |

## 2. 人物(NPC・神話生物)

- `## 主な NPC` の直下の `###` は、すべて人物として扱う。
- それ以外の章では、`####` に `ステータス` / `技能` / `セリフ例` で始まるものを持つ `###` を
  人物として扱う。神話生物は登場する章(多くは `## クライマックス`)の下に `###` で置く。
- 立ち絵は、`###` の直後に単独行の画像 `![名前](/images/<slug>/<name>.png)` として置く。
  人物カードの立ち絵として表示される。2 枚目以降の画像は本文中の画像として表示される。
- 見出しの補足 ` (…)` は、読み仮名・姿の名前(`(怪物の姿)`)を問わず、見出しに小さく添える。
- 1 体が複数の姿を持つ場合は、`#### ステータス (怪物の姿)` のように `ステータス` で始まる
  見出しを姿ごとに分ける。別の存在として書きたい場合は、`###` を分ける。

## 3. 能力値

- 1 行目に能力値を `STR CON POW DEX APP SIZ INT EDU` の順で `項目名: 値` の形で並べ、
  行末を半角スペース 2 つにする。持たない能力値は飛ばす。
- 2 行目以降に副次ステータスを `項目名: 値` で並べる。
- 1 行目が能力値の項目名と `:` で始まる段落は、見出しのレベルによらず能力値の表として
  表示する(場面の中の `####` に置いた敵の `##### ステータス` も同じ)。
- 値は文字列としてそのまま表示する(`15（初期値: 55）`、`105 - 10` など)。

## 4. 判定・正気度・呪文・物品

| 書式 | 構造化表示での扱い |
| -- | -- |
| `**〈技能名〉**` | 判定として強調する |
| `**〈技能名〉** のハード` / `**〈技能名〉** のイクストリーム` | 難易度まで含めて判定として強調する。太字と難易度の間は半角スペース 1 つ |
| `**正気度喪失：成功 ／ 失敗**` / `**正気度喪失：値**` | 正気度喪失として強調し、成功時と失敗時の値を分けて示す |
| `正気度回復: 1D6` | 正気度回復として、喪失とは別の見た目で示す |
| `《呪文名》` | 呪文として強調する |
| `『名前』` | 魔導書・アーティファクトとして、呪文とは別の見た目で示す |
| `**_書名 ページ 項目名_**` | 出典として控えめに示す |
| 上記以外の太字 | 通常の太字(規約では使わない想定) |

`正気度喪失：` は、呪文の説明や報酬の中に書く場合も含めて必ず太字にする。太字でないものは
強調されず(SC-007)、データ適合テストが失敗する。作中テキストのコードブロック内は対象外。

## 5. 作中テキスト・セリフ

- 作中テキスト(日記・手紙・掲示・詠唱文)は、言語指定なしのフェンス付きコードブロックに書く。
  地の文と区別した枠で、改行を保って表示される。
- NPC のセリフは引用(`>`)で書く。引用は「セリフ」の見た目で表示し、引用内の 1 行を
  1 セリフとして区切る。
- GM がそのまま読み上げる描写(読み上げ文)は、1 行目を `[!読み上げ]` だけにした引用で書く。
  引用の中では、改行(行末スペース 2 つ)や判定の太字など、通常の書式がそのまま使える。
  目印の行は表示されず、内容が読み上げ文の枠で囲まれる。

  ```markdown
  > [!読み上げ]
  > 扉を開けると、湿った土の匂いが鼻をつく。  
  > 薄暗い部屋の奥で、何かが **〈聞き耳〉** に引っかかるような音を立てた。
  ```

- 読み上げ文は構造化表示に移行したシナリオでだけ使う。未移行のシナリオでは目印の行が文字列の
  まま見えてしまう。既存の本文を移行するときに読み上げ文へ書き換えるかどうかは任意。

## 6. エンディング・報酬

- `## シナリオ終了` の下に `### ED<番号> 【名称】` を置く。番号と名称を分けて表示する。
- `### その他報酬 (任意)` はエンディングと区別した見た目で表示する。

## 7. 魔導書・アーティファクト

- `### 『名前』` と `『』` で囲んだ見出しは、魔導書・アーティファクトのカードとして表示する。
- 魔導書の属性は、規約どおりの箇条書き(`記載されている言語` `著者` `正気度喪失`
  `クトゥルフ神話` `神話レーティング` `研究期間` `呪文`)で書く。
