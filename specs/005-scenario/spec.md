# Feature Specification: シナリオ一覧・詳細

**Feature Branch**: `005-scenario`

**対象画面**: `/trpg/scenario`、`/trpg/scenario/<シナリオID>`

**Created**: 2026-08-23

**Updated**: 2026-10-03

**Status**: Draft

**Input**: User description: "オーナーが自作したTRPGシナリオを一覧で探し、本文を読める画面。一覧はタイトル・システム・人数・プレイ時間で絞り込める。既存実装の現行仕様を spec として書き起こしたもの。2026-10-02 に、詳細画面を『本文を1本の長い文書として整形表示する』形から『全シナリオ共通の構造化された見せ方』へ作り替える改修を追加。GMが卓で目的の場面・NPC・判定へすぐ辿り着けないこと、Markdownの整形だけではNPCの情報やGMが処理すべき判定をまとまりとして見せられないことが動機。12本を1本ずつ段階的に移行する。2026-10-03 に方針を改め、シナリオごとに配色・レイアウト・演出を自由に決められる専用ページを1本ずつ作る形にした。共通の見せ方ではシナリオごとのデザインや画像の配置、動きのある要素に限界があったため。構造化表示で作った見せ方は部品集として引き継ぎ、NPCのCCFOLIAコマ出力、画像の扱い、フローチャート、既存本文からの下書き作成を加える。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 遊べるシナリオを条件で探す (Priority: P1)

GMをやりたい訪問者として、自分の卓の条件(遊ぶシステム、集まる人数、確保できる時間)に合う
シナリオを絞り込みたい。一覧をすべて開いて確かめる手間をなくすため。

**Why this priority**: シナリオが増えるほど、条件に合うものを見つけられるかが公開の価値を
左右する。

**Independent Test**: 一覧画面で条件を指定すると、一致するシナリオだけがカードとして残り、
件数が更新されることで確認できる。

**Acceptance Scenarios**:

1. **Given** シナリオ一覧を表示している状態、**When** タイトルの一部を入力する、**Then** その
   語を含むシナリオだけが残る。空白で区切って複数の語を入力した場合は、すべてを含むものだけが
   残る。
2. **Given** シナリオ一覧を表示している状態、**When** システムを選ぶ、**Then** そのシステムの
   シナリオだけが残る。選択肢は公開しているシナリオに実際に登場するシステムだけで構成される。
3. **Given** シナリオ一覧を表示している状態、**When** 人数またはプレイ時間を入力する、**Then**
   その値を許容範囲に含むシナリオだけが残る。
4. **Given** 条件を指定している状態、**When** 表示件数を見る、**Then** 「一致した件数 / 全体の
   件数」が示される。
5. **Given** 条件を指定している状態、**When** クリア操作を行う、**Then** すべての条件が解除され、
   全件が表示される。
6. **Given** どのシナリオも条件に一致しない状態、**When** 一覧を見る、**Then** 一致するものが
   ない旨が日本語で示される。

---

### User Story 2 - シナリオごとに専用ページを作り込む (Priority: P1)

オーナーとして、シナリオ1本ごとに専用の詳細ページを作り、配色・レイアウト・演出をそのシナリオの
世界観に合わせて自由に決めたい。共通の見せ方では、シナリオごとの雰囲気を出せないため。

**Why this priority**: 今回の改修の主目的。2026-10-02 に作った「全シナリオ共通の構造化表示」では、
シナリオごとに見た目を変えられず、画像の置き方や動きのある要素にも限界があった。

**Independent Test**: 1本のシナリオに専用ページを作り、そのシナリオの詳細画面だけが専用ページの
見た目になり、他のシナリオの表示が変わらないことで確認できる。

**Acceptance Scenarios**:

1. **Given** 専用ページを作ったシナリオ、**When** 一覧のカードから開く、**Then** 専用ページが
   表示される。URL は従来と同じ `/trpg/scenario/<シナリオID>` のまま。
2. **Given** 専用ページ、**When** 見た目を確かめる、**Then** そのページで決めた配色・レイアウト・
   演出(独自の動きのある要素を含む)で表示され、他のシナリオのページには影響しない。
3. **Given** クトゥルフ神話TRPG向けのシナリオの専用ページ、**When** 末尾を見る、**Then** 二次創作で
   ある旨と権利表記が自動で添えられている。
4. **Given** 専用ページ、**When** ブラウザのタブを見る、**Then** そのシナリオのタイトルが表示
   されている。
5. **Given** 専用ページ、**When** 幅375pxの端末やダークモードで開く、**Then** 横スクロールを
   発生させずに読め、ダークモードでも読める。

---

### User Story 3 - 共通の部品を組み合わせてページを作る (Priority: P1)

オーナーとして、目次・NPCカード・能力値・判定の強調などの部品を、各ページで好きな場所に好きな
順で組み合わせたい。ページごとに一から作らず、GMが卓で使いやすい見せ方を手早く揃えるため。

**Why this priority**: 部品がなければ、専用ページを作るたびに同じ表示を作り直すことになり、
1本ずつ移行していく負担が大きくなる。

**Independent Test**: テスト用のページで各部品を1つずつ置き、それぞれが期待どおりに表示される
ことと、ページの配色に合わせて見た目が変わることで確認できる。

**Acceptance Scenarios**:

1. **Given** 部品集、**When** 専用ページに部品を置く、**Then** 置いた場所・順のとおりに表示される。
   同じ部品を何度でも置ける。
2. **Given** 専用ページの配色、**When** 部品を置く、**Then** 部品の見た目をページの配色に合わせて
   調整できる。
3. **Given** 目次の部品を置いたページ、**When** 目次から章・NPC・エンディングを選ぶ、**Then** その
   見出しへ移動し、見出しは固定ヘッダーに隠れない。幅375pxでも目次を開いて同じ移動ができる。
4. **Given** NPC・神話生物のカードの部品、**When** 見る、**Then** 立ち絵・読み仮名・プロフィール・
   能力値・副次ステータス・技能・セリフ例などが一体分のまとまりとして示される。
5. **Given** 判定・正気度喪失・正気度回復・呪文・魔導書/アーティファクトの強調の部品、**When**
   本文の中で使う、**Then** それぞれが地の文とも互いとも見分けられる。判定は難易度まで、
   正気度喪失は成功時と失敗時の値を区別して示される。
6. **Given** 作中テキスト・セリフ・読み上げ文の部品、**When** 使う、**Then** それぞれが地の文とも
   互いとも見分けられ、原文の改行と強調が保たれる。
7. **Given** エンディング・その他報酬・魔導書の部品、**When** 使う、**Then** エンディングは番号と
   名称を分けて、その他報酬と魔導書はそれぞれの見た目で示される。

---

### User Story 4 - NPC を CCFOLIA のコマとして持ち出す (Priority: P2)

GMとして、専用ページのNPC・神話生物を、CCFOLIA のコマとして手早く用意したい。セッションの
準備で、名前・ステータス・判定用のチャットパレットを手で打ち込む手間をなくすため。

**Why this priority**: GMの準備時間を大きく減らせるが、ページを読む・作るという主目的が先に
成り立っている必要がある。

**Independent Test**: NPCカードからコマをコピーし、CCFOLIA の部屋に貼り付けると、名前・
ステータス・能力値・チャットパレット・メモの入ったコマが1回の貼り付けでできることで確認できる。

**Acceptance Scenarios**:

1. **Given** 能力値を持つNPCのカード、**When** コマをコピーする操作をして CCFOLIA の部屋に
   貼り付ける、**Then** 名前・HP/MP/SAN・能力値・チャットパレット・メモ(プロフィール)の
   入ったコマができる。
2. **Given** コマのチャットパレット、**When** 中身を見る、**Then** 能力値と技能それぞれについて、
   その値で判定するコマンドが並んでいる。
3. **Given** コピーの操作、**When** 成功・失敗した、**Then** その結果が日本語で示される。
4. **Given** 立ち絵や能力値を持たないNPC、**When** コマをコピーする、**Then** 持っている情報だけで
   コマが作られ、欠けている項目は空で出さない。

---

### User Story 5 - 画像を崩さずに見せる (Priority: P2)

オーナーとして、縦長・横長の立ち絵や、地図などの大きな画像を、本文のレイアウトを崩さずに載せ
たい。今は崩れるのを避けるため、立ち絵は正方形に揃え、地図は載せていないため。

**Why this priority**: 専用ページのデザインの幅を広げる要素だが、ページ自体が作れることが前提。

**Independent Test**: 縦長の立ち絵と大きな地図を置いたページを、デスクトップと幅375pxで開き、
画像が切り抜かれず、地図がキャプション付きで表示され、拡大して細部まで読めることで確認できる。

**Acceptance Scenarios**:

1. **Given** 縦長・横長の立ち絵、**When** NPCカードで見る、**Then** 能力値の有無にかかわらず
   どの人物も同じ大きさの顔のアイコンで表示され、周りの文章が崩れない。アイコンを選ぶと、切り抜かれ
   ずに元の縦横比のまま全体が表示される。
2. **Given** 地図などの画像、**When** ページで見る、**Then** キャプション付きで表示され、選ぶと
   拡大して表示される。
3. **Given** 幅375pxの端末、**When** 地図を拡大する、**Then** 細かい文字まで読める。

---

### User Story 6 - シナリオの進行をフローチャートで把握する (Priority: P2)

GMとして、シナリオの場面のつながりや分岐を、フローチャートで一目で把握したい。長い本文を
読み通さなくても、全体の流れと分岐を確かめられるようにするため。

**Why this priority**: GMの把握を助けるが、本文が読めることが先に成り立っている必要がある。

**Independent Test**: フローチャートの部品を置いたページで、場面と分岐が矢印でつながった図が
表示され、幅375pxやダークモードでも読めることで確認できる。

**Acceptance Scenarios**:

1. **Given** フローチャートの部品を置いたページ、**When** 見る、**Then** 場面のつながりと分岐が
   図として表示される。
2. **Given** 幅375pxの端末、**When** 大きなフローチャートを見る、**Then** ページ全体に横スクロールを
   発生させずに、図の中だけを動かして全体を読める。
3. **Given** ダークモード、**When** フローチャートを見る、**Then** 図が背景に溶けずに読める。

---

### User Story 7 - 既存の本文から下書きを作って移行を始める (Priority: P3)

オーナーとして、既存のシナリオ本文から専用ページの下書きを作り、そこからデザインを詰めたい。
1本目の移行で、本文を写し直したりNPCのデータを手で打ち込んだりする手間を省くため。

**Why this priority**: 移行の手間を減らすが、無くても手作業で移行はできる。

**Independent Test**: 任意の1本について下書きを作り、そのまま表示しても従来の表示と同じ情報が
すべて読め、能力値を持つNPCがデータとして入っていることで確認できる。

**Acceptance Scenarios**:

1. **Given** 未移行のシナリオ、**When** 下書きを作る、**Then** 本文の全文と章立てが入った専用
   ページの下書きができる。
2. **Given** 作った下書き、**When** 中身を見る、**Then** 能力値を持つNPC・神話生物がデータとして
   入っていて、NPCカードの部品で表示されている。
3. **Given** 下書きを手を加えずに表示した場合、**When** 従来の表示と見比べる、**Then** 文言・
   数値・画像に欠落や改変がない。

---

### User Story 8 - シナリオを1本ずつ専用ページへ移行する (Priority: P3)

オーナーとして、12本を一度に移し替えず、1本ずつ専用ページへ移行したい。デザインを考えながら
自分のペースで進めるため。

**Why this priority**: 訪問者に直接の価値はないが、これがないと全シナリオのデザインが揃うまで
改修を公開できない。

**Independent Test**: 専用ページを持つシナリオと持たないシナリオが混在した状態で、一覧から
どちらを開いても本文が読めることで確認できる。

**Acceptance Scenarios**:

1. **Given** 一部のシナリオだけが専用ページを持つ状態、**When** 一覧から専用ページのない
   シナリオを開く、**Then** 従来の整形表示で本文全体が読める。
2. **Given** 同上、**When** 専用ページのあるシナリオを開く、**Then** 専用ページが表示される。
   一覧からの辿り方は変わらない。
3. **Given** 専用ページへ移行したシナリオ、**When** 移行前の本文と見比べる、**Then** 文言・数値・
   画像に欠落や改変がない。

---

### Edge Cases

- 条件に一致するシナリオが無い場合は、カードの代わりに一致するものがない旨を表示する。
- 存在しないシナリオIDを直接開いた場合は、本文が空の状態で画面が壊れずに表示され、
  タブの名称はサイトの既定に戻る。
- 人数・プレイ時間の入力欄には数字以外を受け付けず、2桁までとする。0は未入力と同じ扱いに
  する。
- 人数やプレイ時間に幅のあるシナリオ(例: 3〜4人)は、その範囲に入る値で指定したときに残る。
  上限と下限が同じ場合は単一の値として表示する。
- 立ち絵のないNPCも、立ち絵のあるNPCと同じカードで表示する。能力値を持たないNPCでは、
  能力値の欄を空で出さずに省く。能力値を持たず副次ステータス(耐久力など)だけを持つ存在もいる。
- 従来の整形表示では、画像は本文に回り込む今の見せ方のままとする(専用ページの画像の扱いは
  従来表示には適用しない)。
- クリップボードへのコピーがブラウザに許可されていない場合は、コピーできなかった旨を日本語で
  示す。
- コマの画像は CCFOLIA の制約でクリップボードから設定できないため、立ち絵の有無によらず
  コマは画像なしで作られる。画像は GM が CCFOLIA 上で設定する。
- フローチャートや地図が画面より大きい場合は、その部品の中だけで動かしたり拡大したりして
  読めればよく、ページ全体に横スクロールを発生させない。
- 読み上げ文の書き方(目印)は専用ページのためのもので、従来の整形表示では目印が文字のまま
  見えてしまう。従来表示のシナリオでは使わない。
- 下書きの段階で解釈できなかった記述は、捨てずに地の文として下書きに残す。

## Requirements *(mandatory)*

### Functional Requirements

#### 一覧

- **FR-001**: 一覧は、公開しているシナリオをカード形式で並べ、システム・タイトル・対応人数・
  想定プレイ時間・あらすじを表示しなければならない。
- **FR-002**: 訪問者は、カードのどこを選んでもそのシナリオの詳細画面へ遷移できなければ
  ならない。
- **FR-003**: 一覧は、タイトルによる絞り込みを提供しなければならない。入力はふりがなも対象と
  し、空白で区切った語をすべて含むものだけを残さなければならない。
- **FR-004**: 一覧は、システムによる絞り込みを提供しなければならない。選択肢は公開している
  シナリオに実在するシステムだけで構成しなければならない。
- **FR-005**: 一覧は、人数と想定プレイ時間による絞り込みを提供しなければならない。指定した値を
  許容範囲に含むシナリオだけを残さなければならない。
- **FR-006**: 数値の入力欄は数字のみを受け付け、2桁までとし、0は未指定として扱わなければ
  ならない。
- **FR-007**: 一覧は、絞り込みの結果として「一致件数 / 全件数」を常に表示しなければならない。
- **FR-008**: いずれかの条件が指定されているときに限り、すべての条件を一度に解除する操作を
  提示しなければならない。
- **FR-009**: 条件に一致するシナリオが無い場合は、その旨を日本語で示さなければならない。

#### 詳細(共通)

- **FR-010**: 詳細画面は、専用ページを持つシナリオでは専用ページを、持たないシナリオでは本文を
  見出し・箇条書き・表・強調などの書式を整形した従来の表示を示さなければならない。
- **FR-011**: クトゥルフ神話TRPG向けのシナリオの詳細画面には、表示形式によらず、二次創作である
  旨と定められた権利表記を自動で添えなければならない。
- **FR-012**: 詳細画面では、表示形式によらず、ブラウザのタブにそのシナリオのタイトルを表示
  しなければならない。
- **FR-013**: 詳細画面のURL(`/trpg/scenario/<シナリオID>`)と、一覧から詳細画面への辿り方は、
  表示形式によらず同じでなければならない。
- **FR-014**: 詳細画面は、表示形式によらず、幅375pxの端末で横スクロールを発生させずに読め、
  サイトの配色切替(ダークモード)でも読めなければならない。

#### 専用ページ

- **FR-015**: 専用ページは、シナリオごとに配色・レイアウト・演出・独自の動きのある要素
  (タブ、開閉、ハンドアウトを1枚ずつ開くなど)を自由に決められなければならない。あるシナリオの
  専用ページの見た目は、他のシナリオの表示に影響してはならない。
- **FR-016**: 共通の部品集を用意し、専用ページでは部品を好きな場所に好きな順で、何度でも置けな
  ければならない。部品の見た目は、ページの配色に合わせて調整できなければならない。部品は次の
  とおり。
  - 概要(対応システム・人数・プレイ時間・舞台・前提)
  - 目次
  - NPC・神話生物のカード
  - 能力値
  - 判定・正気度喪失・正気度回復・呪文・魔導書/アーティファクト・出典の強調
  - 作中テキスト
  - セリフ
  - 読み上げ文
  - エンディング・その他報酬
  - 魔導書・アーティファクト
  - 画像(立ち絵、キャプション付きの図)
  - フローチャート
- **FR-017**: 目次の部品は、章・NPC・エンディングへの移動手段を提供しなければならない。移動先の
  見出しは固定ヘッダーに隠れてはならない。広い画面では本文を読みながら常に見える位置に、
  幅375pxの端末では必要なときに開いて使える形で示さなければならない。
- **FR-018**: NPC・神話生物のカードの部品は、一体ごとに、立ち絵・読み仮名・プロフィール・能力値・
  副次ステータス・技能・装甲・呪文・正気度喪失・セリフ例・備考のうち持っているものを、
  ひとまとまりで示さなければならない。
- **FR-019**: 能力値は STR・CON・POW・DEX・APP・SIZ・INT・EDU の順で、項目名と値の対応が一目で
  分かる形で示さなければならない。一体が複数の姿を持つ場合は、姿ごとに区別して示さなければ
  ならない。
- **FR-020**: 判定(技能・能力値と難易度)、正気度喪失、正気度回復、呪文、魔導書/アーティファクトは、
  地の文とも互いとも視覚的に区別できる形で示さなければならない。正気度喪失は成功時と失敗時の
  値を区別できなければならない。
- **FR-021**: 作中テキスト(日記・手紙・掲示・詠唱文など)は地の文と区別でき、原文の改行を保って
  示さなければならない。セリフは1セリフずつ区切って示さなければならない。
- **FR-022**: 場面の描写などGMがそのまま読み上げればよい文章は、「読み上げ文」として枠などで
  囲み、地の文・作中テキスト・セリフのいずれとも区別して示さなければならない。文中の改行と
  強調を保たなければならない。
- **FR-023**: 魔導書は、記載言語・著者・正気度喪失・クトゥルフ神話技能の上昇量・神話
  レーティング・研究期間・収録呪文・出典のうち存在するものを、ひとまとまりで示さなければ
  ならない。
- **FR-024**: エンディングは番号と名称で識別できる形で示し、その他報酬はエンディングと区別して
  示さなければならない。
- **FR-025**: 立ち絵は、NPCカードでは能力値の有無によらず同じ大きさの顔のアイコンとして示し、
  選ぶと縦横比を問わず切り抜かずに全体を表示しなければならない。周りの文章のレイアウトを崩しては
  ならない。地図などの図はキャプション付きで表示し、選ぶと拡大して表示できなければならない。
  幅375pxの端末でも、拡大すれば細部まで読めなければならない。
- **FR-026**: フローチャートの部品は、場面のつながりと分岐を図として示さなければならない。
  図が画面より大きい場合は、ページ全体に横スクロールを発生させず、図の中だけを動かして全体を
  読めなければならない。ダークモードでも読めなければならない。

#### NPC のデータと CCFOLIA

- **FR-027**: 専用ページのNPC・神話生物の情報(名前・読み仮名・立ち絵・プロフィール・能力値・
  副次ステータス・技能など)は、本文からの推測ではなく、NPCごとのデータとして持たなければ
  ならない。NPCカードの表示とコマの出力は、同じデータから作らなければならない。
- **FR-028**: NPCカードは、そのNPCを CCFOLIA のコマとしてクリップボードにコピーする操作を提供
  しなければならない。コピーした内容を CCFOLIA の部屋に貼り付けると、1回の貼り付けで、
  名前・HP/MP/SAN・能力値・チャットパレット・メモ(プロフィール)の入ったコマが
  できなければならない。持っていない項目は空で出さずに省かなければならない。コマの画像は
  含めない(CCFOLIA の Clipboard API では外部の画像を設定できないため)。
- **FR-029**: コマのチャットパレットには、能力値と技能のそれぞれについて、その値で判定する
  コマンドを並べなければならない。
- **FR-030**: コピーの成功・失敗は、日本語で利用者に示さなければならない。

#### 移行

- **FR-031**: シナリオは1本単位で専用ページへ移行できなければならない。移行の途中であっても、
  すべての公開シナリオが一覧から開けて本文全体を読めなければならない。対象システムは問わない。
- **FR-032**: 専用ページへの移行で、移行前の本文にあった文言・数値・画像・作中テキストを欠落・
  改変してはならない。
- **FR-033**: オーナーは、未移行のシナリオの本文から専用ページの下書きを作れなければならない。
  下書きには本文の全文と章立てが入り、能力値を持つNPC・神話生物はデータとして入っていなければ
  ならない。解釈できなかった記述は地の文として残し、捨ててはならない。

### Key Entities *(include if feature involves data)*

- **シナリオ**: オーナーが公開している自作シナリオ1本。識別子、タイトル、ふりがな、対象システム、
  対応人数の範囲、想定プレイ時間の範囲、あらすじ、本文を持つ。専用ページを持つかどうかの状態を
  持つ。
- **専用ページ**: シナリオ1本の詳細ページ。本文と、部品の配置、そのページだけの配色・レイアウト・
  演出を持つ。移行後はこれがシナリオ本文の正となる。
- **部品**: 専用ページに置く表示の単位(概要、目次、NPCカード、能力値、表記の強調、作中テキスト、
  セリフ、読み上げ文、エンディング、魔導書、画像、フローチャート)。
- **NPCデータ**: NPC・神話生物1体分の情報。名前、読み仮名、立ち絵、プロフィール、能力値、
  副次ステータス(耐久力・マジック・ポイント・正気度など)、技能、装甲、呪文、正気度喪失、
  セリフ例、備考を持つ(いずれも省略されうる)。複数の姿を持つことがある。
- **CCFOLIAのコマ**: NPCデータから作る、CCFOLIA に貼り付けるためのデータ。名前、
  ステータス(HP・MP・SAN)、パラメータ(能力値)、チャットパレット、メモを持つ。
- **フローチャート**: 場面(ノード)と、そのつながり・分岐(矢印とその条件)からなる図。
- **図**: 地図などの画像と、そのキャプション。
- **下書き**: 既存の本文から作る専用ページのたたき台。本文全文、章立て、NPCデータを含む。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 訪問者が、自分の卓の条件(システム・人数・時間)に合うシナリオを、シナリオを
  1本も開かずに絞り込める。
- **SC-002**: 絞り込みの結果が入力と同時に反映され、待ち時間が発生しない。
- **SC-003**: 一覧から本文まで1操作で到達できる。
- **SC-004**: 幅375px の端末で、横スクロールを発生させずに一覧と本文を読める。
- **SC-005**: オーナーが1本のシナリオに専用ページを作って公開しても、他のシナリオの表示が
  1本も変わらない。
- **SC-006**: 目次の部品を置いたページでは、本文のどの位置からでも、任意の章・NPC・
  エンディングへ2操作以内で到達できる。
- **SC-007**: GMが、能力値を持つNPC1体分のコマを、コピーと貼り付けの2操作で CCFOLIA に用意
  できる。手で打ち込む項目が0件である。
- **SC-008**: 幅375pxの端末で、地図などの図を拡大して、図中の最も小さい文字まで読める。
- **SC-009**: 下書きを手を加えずに表示したとき、移行前の本文と照合して、文言・数値・画像・
  作中テキストの欠落が0件である。
- **SC-010**: 移行の途中のどの時点でも、公開中の全シナリオが一覧から開けて本文全体を読める。

## Assumptions

- サイト共通のヘッダー・フッター・配色切替の仕様は [001-home](../001-home/spec.md) で扱い、
  本specでは繰り返さない([ADR-0013](../../docs/adr/0013-spec-per-screen.md))。
- シナリオはリポジトリ内のデータとして持ち、画面から投稿・編集はできない。掲載内容の更新は
  データの更新で行う。
- 一覧の並び順はデータの登録順に従う。並べ替えの操作は持たない(原則1)。
- 権利表記の自動付加は、対象システムの名称にクトゥルフ神話TRPGを含むかどうかで判断する。
- 本specの一覧部分(User Story 1、FR-001〜FR-009)は既存実装の現行仕様を書き起こしたもので、
  今回の改修では変更しない。
- 2026-10-02 に、詳細画面を全シナリオ共通の構造化表示へ作り替える改修を一度行ったが、
  2026-10-03 にシナリオごとの専用ページへ方針を改めた。共通の見せ方ではシナリオごとの
  デザインができないため。構造化表示で作った目次・NPCカード・表記の強調などの見せ方は、
  部品集として引き継ぐ。構造化表示への切り替えは取り消し、未移行のシナリオは従来の整形表示に
  戻す。
- 主な利用場面は、GMがセッション中やセッション準備で手元の端末で参照することと、訪問者が
  卓に持ち込めるかを判断するために読むこと。
- 専用ページのデザインと、どの部品をどこに置くかはオーナーが1本ずつ決める。全シナリオに
  共通する見た目の決まりは設けない。目次なども部品であり、置くかどうかはページごとに決める。
- 移行の順序と時期はオーナーが決める。全シナリオの移行を完了とする期限は設けない。従来の
  整形表示は、専用ページを持たないシナリオが残る限り残る。
- 移行後は専用ページがそのシナリオの本文の正となる。移行前の本文を並行して保守する
  (二重管理する)ことはしない。
- CCFOLIA のコマの貼り付け形式は、CCFOLIA の公式ドキュメント「Clipboard API (beta)」
  (v1.19.0)に従う。beta のため、実際の CCFOLIA の部屋に貼り付けて確かめる。同 API では
  コマの画像(外部の画像)を設定できないため、コマに立ち絵は含めない(2026-10-03 に
  オーナーと合意)。チャットパレットの
  判定コマンドは、クトゥルフ神話TRPG 7版の書式を前提とする。
- 次の点は本specの範囲外とする: 一覧画面(カード・絞り込み)の変更、画面上での編集機能、
  全シナリオの一括移行、プレイヤー向け/GM向けの表示切り替え(ページごとの演出として作るのは
  妨げない)、印刷用レイアウト。
- 専用ページの形式(地の文を書きやすい形式に部品を埋め込む方針)、部品集の作り方、NPCデータの
  持ち方、下書きの作り方は plan.md で決める。本文の持ち方を変えるのは後戻りにコストがかかる
  判断なので、constitution 原則4に従い ADR で記録する(本文を正とした ADR-0015 の見直しを含む)。
